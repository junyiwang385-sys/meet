# 测试与测评覆盖分析

> 梳理全链路每一步「用什么方法」并核对「代码测试（单元/契约/集成）」与「质量测评」的覆盖，标出缺口。交接用；截至 2026-09-12（以代码为准）。
> **一句话结论**：质量测评（摘要/分章/ASR/VAD/热词，量化 eval）比代码测试扎实；薄弱在**确定性代码单测**（`validation`/`postprocess`/`gateway` 上传）与**长会 + 自动化 e2e 回归**。

## 五、怎么补 / 怎么跑

- 代码测试：新增到 `tests/unit/stages/`（validation/postprocess/transcript/compat_export/enrichment）、`tests/unit/adapters/gateway/`（api 上传路径）、`tests/unit/adapters/board/`（agent api）。跑 `python -m pytest tests`。
- 质量测评：新增到对应 `eval/` 子目录；分章扩场改 `eval/topic_segmentation/`；发言人/action 质量可挂到 `eval/golden_v2/score_candidate` 的维度。
- e2e 自动化回归：以 `ops/e2e/gateway_e2e_client.py` 为基础，加结果结构断言（阶段序列到 `meeting_ready`、`result` 含 summary/chapters/speakers）。
- 长会：需真实 1–2h 音频 + 板端排期；先在 `eval/transcription/`、`eval/golden_v2/` 搭长会样本框架，再实测。

> 诚实边界：本矩阵按当前 `tests/`、`eval/` 实际文件核对；"质量测评"多为 PC 等价替代 + 单/少场（n=3 或 30 场，非大规模 benchmark），绝对值板端会有差异；长会未验。
