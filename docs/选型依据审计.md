# 选型依据审计（每个技术点的决策是否基于测评）

> 诚实盘点：全链路每个技术选型是「评测/实测驱动」、「能力边界/机理驱动」还是「可得性/惯例/推断、未评测」。
> 用途：交接与面试都需要说清"哪些决策有据、哪些是假设待补"——这本身是判断力的体现，而非短板。

## 二、能力边界 / 机理驱动（PC 实测边界 + 论文，非同任务 A/B）

有实测支撑的是**能力画像**，不是"这个方案 vs 那个方案"的直接对照：

- **选 Qwen3-4B**（不更大/不更小）：端侧内存装不下更大模型 + 4B 能力边界 PC 实测(RULER-lite 检索100% / 自主归纳≤30%) + "≥3B 才能利用脚手架"(论文 Big Reasoning with Small Models)。→ **没有做 4B vs 7B / 3B 的同任务质量对照评测**（7B 板端只跑过 smoke）。
- **extract-then-compose / 确定性 DAG 搭骨架 / 一次一任务**：基于 4B 边界机理(检索强、归纳弱)推导，不是 A/B 出来的。
- 依据：`CLAUDE.md`、`small-model-4b-limits`、`meet-summary-4b-limits`；论文 RULER(COLM'24)、Context-Length(EMNLP'25 Findings) 为顶会评审，其余 arXiv 发表状态未逐一核。

## 四、诚实大限（贯穿所有"有测"的结论）

1. 绝大多数是 **PC 等价替代**(Ollama GGUF Q4 / transformers / modelscope)，**非板端 RKLLM/RKNN 复现**——方法论可信、绝对值板端会不同；
2. 多为 **单场 / 少场(n=3 或 golden-30)**，非大规模 benchmark；
3. 金标是 **fable5 生成 + opus5 独立核验的"银标"**，非人工 gold；
4. **长会 1–2h(项目卖点)完全未验**；
5. 板端端到端(前端→板端→回前端)只跑过 **1 次**(未自动化回归)。

## 五、结论与补测评优先级

**一句话**：关键的"要不要做 / 参数怎么调 / 方案哪个好"这类决策**多数有实测或评测支撑**(参数、方法对比、负结果这几块最扎实)；但**"选哪个框架 / 哪个模型"层面基本是可得性 + 能力边界 + 惯例，没做同任务横评**，少数工程数值是估算调参，enrichment / 发言人质量 / beam 等尚无评测。

**若要补齐评测(优先级)**：
1. 长会 1–2h 端到端(卖点，零验证)——最高优先；
2. ✅ enrichment / 发言人纪要 / action 质量评测**已补并扩到 n=30 干净线**(`score_dimensions.py --clean`)——core0.82/决策覆盖0.91/待办覆盖0.93/金句0.85;待办产出2.74=系统性过产(高召回边界);扩样本顺带治本块阶段四类崩溃(见 `RESULTS_dimensions.md`);
3. ✅ 分章 eval 已扩到 4 场(`run_seg_v2_multi.py`)：召回0.30/Pk0.432，多场确认"A层边界召回低"(单场~0.2→4场0.30，非新证伪；粒度差为主)；话语标记 cue 泛化仍未验；
4.（如资源允许）ASR / VAD / 分离框架的横评，把"可得性选型"升级为"评测选型"。
