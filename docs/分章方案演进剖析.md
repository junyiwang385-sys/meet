# 分章方案演进剖析(老方案 → 确定性 A 层)

> 会议纪要分章模块的完整技术弧线:老方案(滑动章节窗口)完整剖析 + 崩因 → 探索过的多方案对比 → 现方案(确定性 A 层 + 字符 bigram 内聚)原理。
> 交接 + 面试底稿。老方案源码来自参考仓 `HawlsonZ/Meeting_Agent`(旧版),现方案为本仓 `src/meeting_agent/stages/topic_segmentation.py`。2026-09-16。

**一句话演进**:老方案把「章节边界判定 + 控制流」双双交给 4B 的语义判断 → 不可复现、4↔26 章摆动;现方案把边界判定挪进**确定性信号(VAD gap / 字符 bigram 内聚谷 / 换人)**,4B 只做块内摘要——这正是 CLAUDE.md 原则 1「智能放确定性 DAG,不放模型自主决策」的实证由来。

## 一、老方案:滑动章节窗口(Sliding Chapter Window)

### 1.1 分块:纯 token 预算的贪心窗口(`_fit_window`)
```python
while end < len(nonempty):
    candidate = nonempty[start:end+1]
    if estimate_tokens(_chapter_window_messages(candidate)) > input_token_budget: break
    last_fit = end+1; end += 1
```
- 从 cursor 起**贪心尽量多塞段**,直到 `input_token_budget = ctx − output − safety` 撑满;
- whole-segment(整段不切碎)、overlap_segments=1;
- **纯 token 预算、零语义**——窗口切点只看 token 数,完全不管话题。

### 1.2 章节边界判定:4B 在窗口内自吐
prompt 让 4B「扫描 Timeline,识别已完成的实质核心章节」,规则全靠自然语言约束:
- 讨论对象/问题目标/方案方向/结论方向**明显变化 → 新建章节**;
- 同一问题连续讨论/回答/确认 = 同一章;开场/寒暄/收尾不成章;
- 只有已形成决定/已转入其他话题的才输出为 `completed_chapters`;仍在比较/等确认/有分歧的不输出。

4B 输出 `completed_chapters[]`(带 core_start_ref/core_end_ref)+ `carryover_start_ref`。**边界 100% 是 4B 的语义判断,无任何确定性算法。**

### 1.3 滑窗:carryover 驱动窗口前进
```python
cursor = 0
while cursor < len(nonempty):
    window_end = _fit_window(nonempty, cursor, budget)      # ① 预算定窗口
    new_chapters, next_offset, carryover = 4B判(window)      # ② 4B判边界+carryover
    if next_offset <= 0: raise "no forward progress"         # ③ 死循环守卫
    chapters.extend(new_chapters)                            # ④ 吃掉已完成章节
    cursor = cursor + next_offset                            # ⑤ 滑到 carryover 点
```
`next_offset` = carryover_start_ref 在窗口的位置(有 carryover)/ 整窗长度(无);**下一窗从 carryover 点重新开始扫**,未完成话题的尾巴被带进下一窗再判。

### 1.4 carryover 详解(滑窗的核心,也是崩点)
**是什么**:窗口按 token 预算硬切,最后一段**几乎必然落在某话题中间**(话题没讲完预算就用光)。这个「留到下一窗继续的未完成尾巴」= carryover。

**判 carryover** = 4B 在每个窗口末尾判:①结尾这段是不是没讲完(还在讨论/等确认/有分歧)?②如果是,它从哪句开始(填 carryover_start_ref)?
- 判「有」→ 该话题不输出为章节,下一窗从 carryover_start_ref 重新扫;
- 判「无」→ carryover_start_ref=null,推进过整个窗口。

**例子**:窗口塞 60 段——段1-30 食堂(讲完✅)、段31-50 宿舍(讲完✅)、段51-60 军训(刚提出、没定⏳,预算到此断)。4B 判:食堂/宿舍输出为章节,军训未完成 → carryover_start_ref=段51 → 下一窗从段51 军训开始重扫,读到军训讲完才作为一章。

### 1.5 不可复现 + 切分混乱的五条根因
1. **边界=4B 语义判断,天生非确定性**:「是否明显变化」是主观语义判断,即使 temp=0 仍随 prompt/输入长度/窗口位置漂移。边界是模型每次现判的,复现无从谈起。
2. **预算切点 × 话题判定「双重耦合」→ 误差雪崩(最致命)**:窗口按预算切、切点必落话题中间 → 4B 每窗末判 carryover → **carryover_start_ref 决定下一窗起点** → **一步判错,后续所有窗口全偏移**。误判 completed→过切(26章);误判 carryover→欠切(尾章吞 53%、只切 4 章)。
3. **复合任务踩 4B 弱项**:一个 prompt 同时要 4B 判边界(篇章理解≤43%)+ 写摘要 + 抽待办 + 判 carryover,长会崩。
4. **参数敏感 → 4↔26 章摆动**:窗口大小/prompt 版本/temperature 一变,边界判定就变。实测 temp0 欠切 4 章 → 调参过切 26 章——**同一策略随参数剧烈摆动,不是切错、是不可复现**。
5. **「no forward progress」守卫暴露脆弱**:主循环需 `if next_offset<=0: raise` 兜底——**设计者知道 4B 可能吐出不前进的 carryover(死循环)**,用模型驱动控制流不得不为其不可靠性打补丁。

## 二、现方案:确定性 A 层 + 字符 bigram 内聚

### 2.1 三步机制
1. **A 层确定性过切** `segment_blocks`:确定性边界信号打分过阈才切,刻意偏向过切;
2. **B 层块摘要**:逐块 A0 隔离受控摘要(不喂上块,防串味),4B 只做块内抽取;
3. **reduce 确定性合并** `_reduce_blocks_to_chapters`:`continues_previous` 由 `_continues_from_boundary` 确定性判——**只有 `opened_by==['size_split']`(纯被预算切碎的续块)并回上章**;gap/cohesion/speaker 都是真边界成独立章。合并时 overview 拼接去重、refs 去重、end_ref 延伸。

**核心思想**:语义边界=真章界;超长切碎=分块副产品需缝回;智能全在确定性骨架,4B 不碰边界。

### 2.2 字符 bigram 内聚——深入原理

**要解决**:算法层面判「话题变了」,需一个可计算的内聚度(相邻内容像不像),内聚低谷=边界。

**为什么字符 bigram**:不用词(中文分词不稳/要词典)、不用句向量(要模型、端侧没有);字符 bigram **无需分词/无需模型/CPU/鲁棒**。

**① bigram 提取** `_char_bigrams`:去空白 → 相邻 2 字滑窗 → **Counter 计数**(高频搭配加权)。`"食堂消毒安排" → {食堂,堂消,消毒,毒安,安排}`。

**② 内聚度=前窗 vs 后窗余弦** `_cosine`/`_cohesion_curve`:每个断点 i,前 window(3)段拼文本的 bigram 计数向量 vs 后 window 段的,算余弦:
```
cos = Σ(left[k]·right[k]) / (‖left‖·‖right‖)    k∈共有 bigram
```
用余弦(而非交集大小/欧氏):**归一化、不受长度影响,只看两边 bigram 分布形状的重叠**。同话题反复用同批字词搭配 → 共享 bigram 多 → cos 高;话题一变用词一换 → cos 低。连成内聚曲线 `curve[i]`,窗口文本 < `cohesion_min_chars`(12)置 None。

**③ 精髓:谷深度而非绝对阈值** `_valley_depth`(TextTiling 思路):
- **绝对阈值行不通**:会议内容同质,余弦绝对值普遍高且波动;绝对阈值调高到处切、调低切不出;且每次换人都带内聚小坑,绝对阈值会把「换人浅坑」全误判成边界。
- **解:看相对低谷深度** = 谷底比两侧峰低多少:
  ```
  depth(i) = max(0, 左峰−谷底) + max(0, 右峰−谷底)
             左/右峰 = 左/右邻 span(4)段内内聚度最大值
  ```
- 两守卫:①只在**局部极小值(谷底)**处计(相邻邻居都不低于自己),避免斜坡多点超阈过切;②`depth ≥ cohesion_depth_threshold(0.30)` 才算信号。
- **这解决换人浅坑**:普通换人 → 小坑 depth≈0 → 不触发;真话题漂移 → 深谷 depth≥0.30 → 触发。把「话题变的深谷」从「换人的浅坑」里分离出来(也是 speaker 只给 0.25 弱权重的原因)。

**④ 融进边界打分** `_boundary_signals`:
```
score = 1.0·[VAD静音≥1.5s]  +  1.0·[cohesion深谷≥0.30]  +  0.25·[换人]
if score ≥ 1.0: 切
```
单深谷(1.0)够切;单换人(0.25)不够;换人+浅坑仍不切(浅坑不算 cohesion);深谷+换人(1.25)最强真边界。

**⑤ 诚实局限**:靠「用词变化」抓边界。**平滑议题 + 密集问答**的会前后都在同一领域用相似词、**没有深谷**,字符 bigram 抓不到——这类会真边界是发言权转移(主持人交接)驱动,得靠话语标记补(见 §三方案4)。「没有单一信号通吃所有会」的由来。

### 2.3 句向量后端(可插拔)
`embed_fn` 可注入(bge / sentence-transformers)→ 窗口取段向量均值算余弦。语义更准,但**端侧无模型故默认字符 bigram**;且句向量余弦基线更高,需配套调 depth 阈值(谷深度是相对量仍适用)。

## 三、探索过的其它分章方案(对比)

| # | 方案 | 具体做法 | 结果 / 机理 |
|---|---|---|---|
| 1 | **主发言人切换**(确定性) | 追踪每时段主发言人,主发言人切换处定边界(一人主导一议题) | 四方法 **57% 最优、泛化最稳**;是桌面 combo「方案1 定边界 + 4B 命名」的边界法 |
| 2 | 议程对齐 | 用 agenda 条目对齐转写定章界 | 43%,**边界漂**(实际顺序≠议程:跳项/回头/插话) |
| 3 | 句向量 embedding 内聚(bge-small-zh) | bge 编码段向量,窗口质心余弦谷=边界 | ⚠️ 可插拔不默认。教训:①须用谷深度(相对);②bge 绝对相似度合并会全塌成 1 章(会议同质、相邻余弦>0.8);③某些会句向量召回(2/10)反<字符(5/10) |
| 4 | **话语标记 discourse cue**(单场最优) | 正则+轮次检测主持人交接/「下一位」/学员提问/收尾——检测**话语行为**非语义漂移 | 🏆 单场 Pk 0.497→0.190、边界召回 2/10→7/10;但 cue 词表从本会归纳(**过拟合**)、跨会未泛化、未接进生产 |
| 7 | 4B 主题判定 | 4B 逐段/逐窗判主题,主题变=边界 | **29%(最差)**——4B 自主主题判定=篇章弱项,和老滑窗一个病,**直接印证「别让 4B 判边界」** |
| 8 | 细切→二次合并(追阿里粗档) | bge 细切 26 章 → **4B 逐对判「同议题?」合并** → 20 章 | 命中阿里 77%/飞书 82%,但仍偏飞书派;见 §四 |

**信号类型总览**:
| 信号 | 方法 | 靠什么抓边界 | 死穴 |
|---|---|---|---|
| 语义内聚 | 字符 bigram(现)/句向量 | 话题词汇/语义漂移 | 平滑议题、密集问答无漂移→抓不到 |
| 话语结构 | 话语标记/主发言人 | 发言权转移/主持人交接 | 依赖清晰主持结构;cue 过拟合 |
| 外部对齐 | 议程 | 议程条目 | 实际顺序≠议程→漂 |
| 模型判定 | 4B 主题/老滑窗 | 4B 自己判 | 篇章弱项、不可复现(29%/4↔26 章) |

**核心认知**:没有单一信号通吃所有会——语义内聚对「议题硬切换的会」好、话语结构对「平滑问答的会」好;**让 4B 自己判永远最差**。故生产选确定性信号打底、坚决不把边界交给 4B。

## 四、方案8 深挖(有效却不采用的取舍)

**用什么模型**:①bge-small-zh-v1.5(细切);②**Qwen3-4B 本身**(PC 上为 Ollama `qwen3:4b`)做「逐对判同议题」的二次合并——**不是另找大模型救,是让项目自己的 4B 做粗粒度归纳**。

**最终没采用**(生产用确定性 A 层)。三条原因:
1. **目标没达成**:细切 26→合并 20,但「命中≠同粗」,20 章**仍偏飞书派**,压不到阿里 13;
2. **手段违背核心认知**:二次合并靠「4B 逐对判同议题」= 粗粒度议题归纳(4B 弱项),**又把归纳请回给 4B**,与整条演进的「别让 4B 判归纳」冲突;
3. **粒度无标准答案**:飞书细/阿里粗、85% 重合、没对错——不值得为追阿里引入「4B 归纳」这个不稳定环节。倾向「别硬追,20 章覆盖两家边界已够」。

**对照实验(诚实)**:
- 四方法(embedding/4B 主题/议程/主发言人)做了**同口径「命中真边界%」对照** → 方案1(57%)胜出;
- 方案8 **没进这场对照**——它单独测「对飞书/阿里边界重合率」(82%/77%),**与四方法非同一口径同金标**;
- 严格讲方案8 有对比数据、**无 clean head-to-head A/B**;弃它是「追阿里是否值得 + 手段违背原则」的判断,非被某方案在同实验里比下去。

> 如果换 opus 这类大模型做合并判定,可能追得上——但**端侧没有大模型**,这条路在端侧走不通。

## 五、新旧对比 + 第一性

| | 老方案(滑动章节窗口) | 现方案(确定性 A 层) |
|---|---|---|
| 分块 | 确定性 token 预算 | 确定性**语义信号**(gap/cohesion/speaker) |
| **章节边界** | **4B 自吐**+ carryover 滑窗 | **确定性信号定,4B 不碰** |
| 可复现 | ❌ 4↔26 章摆动 | ✅ 稳定 7-8 章 |
| 4B 职责 | 判边界+摘要(复合,踩篇章弱项) | 只块内摘要(受控抽取,强项) |
| carryover | 滑窗靠 carryover_start_ref 推进 | A0 隔离不喂 carryover;只对 size_split 确定性缝合 |
| 评测 | — | 对银标细章边界召回~0.30/Pk0.432(偏粗,含粒度差) |

**第一性**:老方案把最需要篇章理解的「边界判定」压在 4B(其弱项)上,还让它驱动控制流 → 不可复现;现方案把边界判定确定性化,4B 退回它强的块内抽取。**从「不可复现」到「稳定可回归」,代价是分章粒度偏粗。**

## 六、面试弧线(完整,不夸大)

> 「老方案用**滑动章节窗口**让 4B 自吐边界 + carryover 滑窗,结果**同一策略随参数在 4↔26 章剧烈摆动、不可复现**(根因:预算切点×话题判定耦合导致 carryover 误差雪崩 + 4B 篇章弱项)。我把边界判定从模型挪进**确定性信号**(VAD gap / 字符 bigram 内聚谷深度 / 换人),4B 只做块内摘要——**从『不可复现』到『稳定 7-8 章』**。中间试过 embedding/话语标记/主发言人/议程/细切合并等 6 个方案,认清『没有单一信号通吃、让 4B 判边界永远最差』;甚至一个『4B 二次合并追竞品粗档』的方案**验证有效我也没用**——因为它又把归纳请回给了 4B、违背核心原则。代价诚实说:分章粒度偏粗(对细章召回 0.30),且分章粒度本身无标准答案。」

**守边界**:话语标记只单场验证、cue 过拟合、未泛化未上生产;别夸「通用降 X%」。展示的是**量化 + 自我证伪 + 机理定位 + 取舍判断**,比任何单一准确率都值钱。
