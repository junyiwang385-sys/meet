## 二、当前纪要策略的问题评估

采样参数（`main.py`）：`temperature=0 / server_temp=0 / top_k=1 / top_p=1` —— **纯贪心解码**，输出确定可复现。

### 2.1 章节划分任意（不是随机，是语义任意）
- 贪心解码下不存在 RNG 抖动；"随机"的本质是**语义任意性**：输入稍变（多一句寒暄、ASR 错一词），边界大幅漂移。
- 根因：让 4B 直接输出 `core_start_ref`/`core_end_ref` 这种**精确 segment ID 当章节切点**，这是话题分割里最难的一种形式。话题边界本身模糊，4B int4 内部没有稳定信号支撑离散边界决策 → 边界必然任意。
- **ref 一符两用**：`rN` 既是"引用证据"又是"章节分界"，两种语义互相干扰。
- 提示词要求"结论方向变化必须新建章节"——要 4B 在长时间轴上跟踪元认知信号，做不到。
- **校验层救不了**：`validation.py` 只查结构（refs 存在、`start_ms ≤ end_ms`、无占位词）；`_normalize_overlapping_core_candidates` / `_expand_core_chapter_ranges` 那套修复**只修区间重叠/逆序/越界，从不判断切点语义对不对**。这套修复机器的存在，本身就是"原始输出不可靠"的证据。

### 2.2 摘要字数少（软约束零强制）
- `validation.py` **无任何长度校验**：`clean_text` 只做去空白 + 占位词过滤，`normalize_summary` 全程不看字数。"约 300-500 字"纯属提示词许愿，给 80 字也照样 `status: pass`。
- 放大因素：贪心解码（top_k=1）天然偏短；int4 量化最先丢的就是"字数/句数"这类软指令遵循；单请求多目标稀释注意力。
- 提示词里"overview.refs 不要只引用开场的一段"是**已踩过 lost-in-the-middle 的补丁痕迹**。

### 2.3 单请求 `single_request_all_features` 在 4B+int4 下不可行（作为质量主路径）
- `plan["full_request_fits"]` 为真时走单请求，让 4B 在**一次前向**里同时完成：话题分割 + 精确边界 ref + 多段摘要 + 发言人归因 + 待办抽取，输入是整场时间轴。
- 对 4B int4 是几乎不可能稳的复合结构化任务：长输入注意力稀释 + lost-in-the-middle；多层嵌套 JSON + 大量精确 ref → 坏 JSON/幻觉 ref/截断风险叠乘；int4 让每项失败率再上台阶。
- smoke 能过是因为测的是干净短音频；真实 1-2h 长会这条路的分割质量与 overview 丰度都会崩。
- **自相矛盾**：项目另一条 `sliding_chapter_windows` 明明是解耦的 map-reduce（架构对），单请求却把它塞回一个请求，违背了自己的 map-reduce 原则。

### 2.4 "直接通过提示词生成" —— 核心设计气味
章节划分 100% 委托 4B 徒手生成，零算法先验。话题分割恰恰最该给模型**脚手架**，而不是让它凭空发挥。

## 三、目标方案：确定性四层流水线

**核心思路：把"话题分割"从模型手里拿走一部分，让模型只做它擅长的"给定一段文本写摘要 / 做二分类判断"。智能放在 Python 的 DAG 里，不放在模型的自主决策里。**

### A 层｜确定性话题分割（CPU，无 LLM）
- 用前半链路本来就有的信号做切点：speaker 切换点（已有）、VAD 长静音 gap（已有），叠一个 ASR 文本上的轻量词汇内聚度 / 滑窗话题漂移打分（TextTiling 思路，纯 CPU）。
- 产出一串**候选块（block）**，受 token 预算约束。**宁可过切**——A 层只保证"切得不漏"，语义合并交给后面。
- 这一步直接消灭"边界任意"：边界不再由模型凭空生成。
- 架构文档里"speaker切换 → VAD gap → 句末标点"的确定性切分器，本就该前置到 LLM 之前，A 层把它接回来。

### B 层｜逐块处理（NPU，map，一次调用一职）
- 每个 block 一次 LLM 调用，**只干一件事**：总结成 `{title, summary(200-400字), key_points, refs}`。小而聚焦 → 4B 稳、肯写长、JSON 不崩、字数好强制。
- 叠一个模型能可靠做的**微决策**替代徒手分割：给相邻两块问"是否延续上一块话题？yes/no"（二分类，4B int4 做得了），用它合并 A 层的过切 —— 这是"模型辅助分割"而非"模型发明分割"。

### C 层｜归并（reduce）
- 相邻同话题块合并 → 最终章节。
- 各块摘要 reduce → 全文 overview（滑窗路径 `_full_summary_messages` 已这么做，保留）。
- 发言人：按 speaker 分组，逐人/分批一调用（已有，保留）。
- 待办：逐块抽取 → 一次去重复核（已有，保留）。
- **overview 永远走 reduce 侧生成**，不再由单请求顺带吐——这是它现在写得薄的直接原因。

### D 层｜校验 + 落盘（+ 可选自检）
- 保留现有 grounding 校验（refs 必须存在、owner/deadline 无依据即清空）——全项目最值钱的部分，别动。
- **补长度门 + 触发重试**：overview/章节摘要低于阈值，像现在处理坏 JSON 一样受控重试（重试框架现成）。
- 可选一个 "critic" 节点复查幻觉/覆盖度，但**固定一次调用，不做循环**，默认关闭，等有 golden set 再评估。

## 四、Agent 边界判断

**纪要生成本身必须是确定性工作流，不引入自主 Agent。** 理由：

1. 必须确定性 + 可断点续跑：现有 resume 靠 `config_identity` / `request_fingerprint` 指纹复用，依赖请求图稳定；Agent 动态规划会让指纹复用、幂等、golden set 回归全部失效。
2. 4B int4 的 function-calling / planning 不可靠（架构文档 P1 已有此判断）。
3. 离线批处理 + 单 NPU，任务图先验已知，没有"临场决定调哪个工具"的场景；Agent 动态编排纯增开销与延迟。
4. 可观测/可调试：固定 DAG + 每节点 artifact 才能逐节点校验回归；Agent trace 在 4B 上既不稳又难复盘，与现有 runlog/artifact 体系冲突。

**Agent 真正的位置在未来的交互层**：对生成好的纪要做多轮追问/问答（RAG-over-minutes），数据源固定、工具明确、失败可容忍，值得做。

若为叙事需要把 B/C 层专职 LLM 节点称作"角色化 agent"，前提是它们**无状态、单轮、代码调度**——区别只在措辞，不在架构。

## 五、改造 checklist（保留 vs 改）

| 现有 | 处置 |
|---|---|
| 窗口 map-reduce 骨架（sliding_chapter_windows） | 保留并升级为主路径 |
| `single_request_all_features` | 降级为"极短单主题会"快路径，不再承载质量 |
| 让模型吐 `core_*_ref` 当切点 | 删掉，换成 A 层确定性切点 + B 层 yes/no 合并 |

### 预算与 think 分配（2026-08-26，同批待测）

- **块软目标大小**：A 层 `target_block_tokens=1800` + `min_block_chars` 60→400。原来块尺寸只有硬上限(≈12288)和硬下限，中间无约束——长而平滑的单人/单主题内容会一路撑到硬上限，架空 B 层"小而聚焦"的初衷。软目标让块攒过 ~1800 就在最弱内聚点切开，落进 4B 舒适区；`boundary_reason_counts.size_split` 可观测。
- **think 分 kind**（4B int4）：`_apply_think_directive` 对抽取/压缩类（block-summary/full-summary/speaker-batch）追加 Qwen3 `/no_think`，把紧张的输出预算全留给答案、避免 thinking 吃掉答案导致 JSON 截断；判断类（action-review，及将来专名纠错）保留 think。原 SYSTEM_PROMPT 是"允许 think"（可开可不开、不可预测），现改为按 kind 明确开关。
- **per-kind 输出预留**：`_KIND_OUTPUT_TOKENS`（block 1200 / overview 1400 / speaker 1400 / action-review 3072），按 kind 传 `max_tokens` 给 server。
- **overview 接地门槛加宽**：自适应 overview 改用 overview 自己的输出预留(1400)算 `overview_budget`（输入预算 ctx-1400-512=14472，大于全局 12800），更多会留在 `source_timeline` 接地版。
- **待板端校准**：`chars_per_token=1.3` 对纯中文 Qwen3 偏保守（实测约 1.5~1.7），回归时 dump `估算 vs 实际 usage` 校准；`/no_think` 是否被 rkllm3-server 支持须实测。

### A 层过切机制修复（segmentation.v2，域无关，2026-08-27）

基于全链路回归的根因(cohesion 被说话人绑架：换人→不同用词→字符 bigram 必然下降→绝对阈值必触发，实测 30/36 边界是 speaker+cohesion 共现，等于在做说话人轮次切分)，把切分判据从"绝对内聚度阈值"改为**低谷深度**(TextTiling 思路)：

- **内聚度深谷**：先算全局内聚度曲线，只在**局部极小值且深度 ≥ `cohesion_depth_threshold`(0.30)** 处才算 cohesion 信号——普通换人的浅坑不再触发，真话题漂移的深谷才触发。局部极小值判定避免谷斜坡多点同时超阈值造成过切。
- **speaker 降为弱助推**：`speaker_weight 0.5→0.25`，单独不足以切(<阈值1.0)，只能给"深谷+换人"的真边界加分。`cohesion_weight 0.6→1.0`(深谷可单独切，抓同一说话人的话题转移)。
- **性质**：机制域无关(任何多人会都有"换人≠话题变")；阈值保守可调，**须用真实产品技术会素材校准**。
- 单测覆盖"真话题漂移切 / 单话题内换人不过切"；`plan.segmentation.boundary_reason_counts` 观测 speaker 驱动的假边界是否消失。

> 注意：章节目标粒度、摘要 rubric、填哪些字段是**域相关**的，销售培训回归不能代表产品技术会，这些待真实素材再定。

### 发言人总结重构 + unknown 顺延（2026-08-27，全链路失败复盘）

全链路回归失败于 speaker-batch：`missing speaker summaries` → 返回码 7 → 整场会失败。复盘根因（见 run_report + blocks 明细）：7 人挤一批 + `/no_think` → 模型暴吐 refs 撞 max_tokens=1400 截断 → 反馈重试矫正过头 → 顺序编造 refs（sp0=[r1,r2,r3]…不属于本人）→ 校验按"ref 须属于该 speaker"全丢 → 判漏 4 人。据此重构：

- **best-effort，绝不 raise**：`_validate_speaker_batch` 改为缺 speaker 就跳过 + 记，绝不因发言人总结这一 best-effort 增强而使整条 pipeline 失败（原设计是最后一步 reduce 硬门，一挂全丢已算好的 blocks/chapters/overview/action）。
- **refs 由代码指派**：模型只写 overview 文本，refs 从该 speaker 自己最长的段取（`SPEAKER_REFS_PER_SPEAKER=2`）——从根上消灭编造证据，同时大幅缩小输出、消除截断。
- **过滤 unknown 与琐碎发言**：`_build_speaker_documents` 跳过 unknown、过滤总字数 `< SPEAKER_MIN_CHARS(80)` 的 speaker，不给噪声/"只说了对"的人硬凑总结。
- **提示词**：去掉"每人必须输出/refs 归属"硬约束，只要 speaker_id + overview，允许省略实质过少者。
- **unknown 顺延（前端展示）**：`display.py` `_carry_over_unknown_labels` 把 unknown 段的展示标签顺延归并到相邻已知说话人（先向前、开头再回填），保留 `raw_speaker_id`；只影响展示，不改 canonical 与 refs。

### 块摘要 extract-then-compose（级别一，2026-08-27）

回归证据（销售会）显示一次直接生成必然翻车：块摘要把结构性结论（"销售三原则：好/物有所值/创造需求"）抽象抹掉、把锚点（微波炉例子）蒸发、还改写（物有所值→"合理定价"）。4B int4 在"读→判重点→压缩→成文"一步里会跳过最难的 salience 判断，退化成"会议讨论了X、强调了Y"的流水账。

据此把块摘要改为**先抽取、后成文（一次调用）**：

- **输出 schema 先抽后写**：`key_points`（结论/决定/方案，封顶 6）→ `anchors`（例子/数字/专名，封顶 8，原样保留）→ `summary`（据前两者成文，结论前置，必须涵盖 key_points 并嵌入 anchors）。schema 顺序把"想清楚重点"变成**有用可审计的显式输出**，而非扔掉的 think（think 留给推理即弃的判断类）。
- **防泛滥**：每项封顶 + 去重 + "宁缺毋滥"定义 + 借**话语标记**提示（"总结/第一二三/所以/结论是"通常是重点，非关键词硬匹配）。
- **不用代码关键词判重点**（死板+泛滥，且是纠错的工具）；用少量有界的 aspect 语义提问让模型有界抽取。
- **合并去冗余**：`_reduce_blocks_to_chapters` 对近重复的续块摘要（字符 bigram Jaccard ≥0.8）不再"；"拼接，key_points/anchors 合并去重（治 blk-7/8 冗余缝）。
- **成本**：级别一仍是一次调用，多生成 ~250 输出 token（比原 think 的 ~500-800 还少）；实测 decode ~80 tok/s、prefill ~786 tok/s，8 块约 +25s（占全程 ~5-6%，分段/ASR 才是瓶颈）。

**域边界**：extract-then-compose 的**结构域无关（已落地，aspect 用通用占位）**；"抽取哪些 aspect"（技术会：决定/待办/方案取舍/风险/参数）**待真实素材调**，届时可把 key_points 正式接入 schema 的 decisions/key_points 字段。级别二（真多轮抽取 pass）留待级别一不够时再上。

### 领域画像解耦（2026-08-27）

规划路线：**先测单领域 → 会议类型识别选对应领域**。据此把"抽取什么"（域相关）从主管线（域无关）解耦：

- 新增 `stages/summary_profiles.py`：`DomainProfile`（aspects / anchor_guidance / discourse_markers / caps / summary 目标区间 / summary_min_chars / fill_schema_fields）+ `GENERIC_PROFILE` + `PROFILES` 注册表 + `get_profile()`。域知识全在这里。
- `product_summary` 只消费 profile：`_block_summary_messages` / `_validate_block_summary` 从 profile 渲染抽取维度与封顶；`ProductSummaryConfig.profile` 默认 `GENERIC_PROFILE`。**切块/逐块/reduce/校验/合并全都域无关，一行未动，行为不变（109 测试通过）。**
- 三阶段：**① 解耦（已做，通用占位）→ ② 单域打磨（写 `product_tech` profile、pin 死跑，等真实技术会素材）→ ③ 会议类型识别**（`select_profile` 分类选画像，粗分类判断、可回退用户指定/默认，有多域需求时再做）。
- **加新域 = 加一个 profile，不碰核心**；主框架永远域无关。

### 专名纠错（P1）的定性结论

纯模型直接纠错**不可行**：这是知识问题不是推理问题——4B 参数里没有企业私有专名，无法凭推理恢复，且会幻觉式过度纠正。**必须引知识库，但用广义 RAG（关键词/拼音检索表），不是向量 RAG**（向量库需 embedding 模型，吃 NPU/内存，违背纯板端）。模型角色压到最窄：给可疑词 + 检索候选 + 上下文，只做"换不换/换成哪个"的**判断**（think-on，复用 action-review 骨架）。分工：主题识别(LLM) → 领域包加载(代码检索) → 拼音/编辑距离找可疑词(代码) → LLM 判定替换。词表来源：通用层 LLM 离线生成 + 人工补企业专名(护城河) + 历史纪要自增长。
