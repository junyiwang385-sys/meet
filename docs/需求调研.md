## 0. 先分清「两代产品形态」（最重要）

材料横跨两个阶段，形态不同，读任何 PRD 前必须先定位在哪一代：

| | 早期（发现阶段 / v0.1 / v0.2） | **当前落地（MVP v1.0 + API 契约 v1.0）** |
|---|---|---|
| 定位 | 敏感企业固定会议室的**会议投影终端** | **内部技术演示版** |
| 录音 | 现场阵列麦克风、会中处理 | PC 选**本地 WAV**（现场录音延期） |
| 确认 | 会尾**大屏多人共同确认** | PC 端**单人**查看/修正/确认 |
| 分发 | USB(PDF+manifest) 受控分发 | 本地 **HTML/TXT/JSON**（USB/PDF 延期） |
| 权限 | 完整多角色权限 | 单一演示操作人，不做真实身份认证 |

后者是当前真正要落地的东西，前者是它的需求与决策来源。

## 1. 需求调研总结

### 1.1 目标用户与场景（回答"系统面向谁"）
- **ICP**：50–500 人的**制造 / 研发 / 工程 / 工业设计企业**；配投影设备的固定会议室；3–15 人、每周多次项目/管理会议；**不愿音频与纪要上第三方云**；内部会议经授权可录音。**付费主体是企业/部门，不是个人。**
- **四类角色诉求**：使用者（PM/主持人，要结论+待办+责任人）、购买决策者（行政/IT，要不依赖云、易部署）、安全把关者（信息安全/法务，要不出设备+权限/删除/审计）、受益者（全体参会人，要"谁在何时做什么"）。
- **市场优先级**：P0 制造/研发/工程企业（采购链路可控）；P1 央国企/政府/金融/法律/医疗（保密强但认证周期长）；P2 教育/培训/咨询；P3 家庭（不优先）。
- **核心场景**：项目/研发/里程碑评审、质量/生产/供应链会、需求与方案评审、招投标讨论；首版聚焦**普通话、3–15 人、30–120 分钟、固定座位**。
- **MVP 阶段唯一用户收窄为「研发评审人员／演示操作人」**，以"主持人/确认人"身份操作但不做真实认证。

### 1.2 用户最想要的前三项功能
1. **自动生成可执行的结构化纪要**——要的不是逐字稿，而是"讨论了什么/决定了什么/未解决/接下来做什么/谁负责/何时完成"，配会尾投屏确认。
2. **准确的离线转写与发言人识别**——3–15 人、发言人区分、企业人名/术语词库；关键链路是"发言人→提议/决策→待办→责任人"。
3. **完全本地处理与安全流转**——断网可用、本地加密、权限、自动删除、受控导出、操作审计、物理静音、录音状态可见。
> 三者是价值链：转写决定可信、结构化决定效率、本地安全决定敢不敢用/能不能采购。

### 1.3 访谈要点（⚠️ 虚拟场景，非真实客户证据）
- 虚拟受访者=约 80 人智能硬件公司研发负责人。
- 最容易遗漏"最终到底决定了什么"，其次是待办的责任人与截止时间；曾因纪要只写"接口需要调整"未记具体方案导致约**两天返工**。
- 最想解决**行动项闭环**（任务-责任人-截止-依赖）+ 结论可追溯到原始发言。
- **愿意会尾花 1–3 分钟投屏确认**，前提是只展示决策/待办/责任人/截止/待确认问题（非全文），可直接改+勾选，且 ≤3 分钟。

### 1.4 需求假设 P0/P1/P2（全部"待验证"）
- **P0（9）**：断网可用；授权录音+物理静音+状态可见；离线普通话转写+快速纠错；基础发言人分段+不确定标记；结构化可执行纪要；会尾 1–3 分钟共同确认；主持人确认才成正式纪要+状态机；本地加密+分层删除+受控导出；条目级原始发言证据。
- **P1（8）**：企业词库、参会人/声纹管理、跨会议待办追踪、角色权限、局域网受控分发、会前议程+上次待办、分层保存、日程/任务系统连接器。
- **P2（6）**：多语言翻译、实时字幕、已确认纪要本地问答、汇报材料/PPT、跨会议聚合、大会议/远场。
- **统一验收原则**：AI 输出默认草稿；不确定必须标"待确认"不补全；关键字段可核对；正式纪要记确认人/时间/版本；人工修改优先并锁版本；准确率/时延/价格一律 TBD/初始目标。

### 1.5 竞品横向结论与差异化切入
- 对比 6 家：飞书妙记、科大讯飞、腾讯会议、钉钉 AI 听记、Teams、MAXHUB V7550。**均未实测**（仅飞书 1 个 33 分样例、无 Gold），矩阵是"证据状态"非评分。
- 各家侧重：飞书=云端内容/协作基线；科大讯飞=唯一有离线/私有化+ASR/声纹方向；腾讯会议=云会议原生 AI+章节可跳转；钉钉=组织协同+主张待办/责任人（未验证）；Teams=企业治理最完整（Recap/Copilot/Purview 审计）；MAXHUB=固定会议室硬件形态。
- **六家共同证据空白 = 本产品主轴**：①会尾大屏共同核对；②AI 草稿经授权确认才成正式纪要；③正式纪要记确认人/时间/版本/分发；④每条决策/行动项独立关联原始发言证据；⑤缺责任人/截止时间时**显式提示而非 AI 补全**；⑥全链路端侧断网闭环。
- **中心对象是"经共同确认的决策/行动项/正式纪要"，不是逐字稿。**

## 2. MVP PRD 导读（原文见 [`docs/需求调研/PRD_端侧本地Agent智能会议投影系统_MVP_v1.0.md`](需求调研/PRD_端侧本地Agent智能会议投影系统_MVP_v1.0.md)）

### 2.1 唯一 MVP 目标与要回答/不回答的问题
- **验证最小闭环**能否在"开发板 NPU + 局域网 PC"独立跑通：`PC选WAV → 局域网发板 → NPU 转写/说话人/分章/纪要 → PC 分阶段展示 → 用户核证据并修正 → 确认生成正式纪要 → 本地存 HTML/TXT/JSON → 音频可独立删除`。
- **明确不回答**：真实市场需求、用户是否愿会尾确认、整体准确率是否达生产、是否可量产、最终硬件成本。

### 2.2 已确认边界（§1.1）
内部技术演示版；Agent 在板端 NPU、PC 为局域网展示操作端；输入=单个本地中文 WAV，**最长 120 分钟（输入上限目标，非已验证性能）**；**一次只处理一个任务，不并发不排队**；输出=全文/章节/回放/发言人/决策与待办；确认后生成 HTML+TXT+JSON；只在 PC—板局域网闭环、不依赖公共云；单一操作人整体确认；验收=功能闭环+描述性内容验证，**不冻结整体准确率或 G2/G3 阈值**。

### 2.3 范围内 / 延期 / 不做
- **范围内（P0，22 项，`MVP-FR-001`~`023`）**：PC 局域网 Web 入口；全文/章节/发言人纪要；全文回放（逐字稿+发言人+时间线同步）；决策与待办；WAV 校验（≤120min）；局域网传输；NPU 处理（**须真机跑，不得预置结果冒充**）；分阶段状态（**不显示无法证明的精确百分比**）；自动分章+章节增删改重命名重生成；发言人标签最小修正；证据跳转；决策/待办人工增删改；AI 草稿与正式纪要分离；单人整体确认；版本+确认+最小审计；本地加密存储；音频独立删除；三文件输出；取消/失败重试/局域网中断处理。
- **延期（P1）**：现场录音、真实录音授权/撤回/物理静音、逐字稿人工编辑、非 WAV 格式、多任务/队列/断点续传、多用户并发、真实多角色权限/身份认证、PDF/USB/外部分发、跨会议跟踪、G2/G3 自动评分、企业级密钥管理。
- **明确不做**：运行时调云端 ASR/大模型、真实敏感会议试点、生产级合规承诺、自动补造字段、发言人自动实名、模型输出替代官方 TextGrid/RTTM、多语言/翻译/实时字幕/情绪/数字人/自动 PPT。

### 2.4 关键产品规则（差异化与质量底线）
- **纪要=数据对象**：Meeting/TranscriptSegment/Speaker/ChapterSummary/FullMinutes/SpeakerMinutes/Decision/**ActionItem**/EvidenceLink/DraftMinutes/FormalMinutes/AuditEvent。
- **ActionItem 团队/个人分离**：`responsible_team` / `individual_owner` / `ownership_status`(四值) / `deadline` / `evidence_links[]` / `confirmation_status`。提议者不自动成责任人；团队明确但个人缺失则保留团队、个人置空；截止缺失置空、相对时间不自动转具体日期；**整体确认不自动把 owner 状态改为已接受**。
- **防编造（§11.2 质量底线）**：不从发言人推断姓名/部门/职位；不从提议者推断责任人；不从相邻条目复制截止；"有人建议"不写成决策；模型最高概率值不当确定事实；不用飞书模型输出替代官方 TextGrid/RTTM。**宁可显式缺失，不把不确定写成事实。**
- **待确认状态机**：`supported/evidence_missing/conflict/low_confidence/field_missing/human_resolved`；确认工作流 `active/deferred/overdue/abandoned`（overdue 不自动正式化或删除，abandoned≠删除）。
- **草稿→正式版本**：AI 草稿→待确认→正式纪要→修订草稿→新正式版本；正式确认前须满足所有阶段完成、决策/待办已核对或保留待确认、缺失字段留空、冲突/低置信未被静默确定化、用户明确点击、记录确认人+时间+版本+审计。正式确认**不要求**每责任人单独接受、多人签署、G2/G3 达标。
- **离线约束**：PC 明文→PC 加密工作区→局域网临时副本→板端加密临时区→NPU→回传 PC 加密工作区；运行时不外发；**加密失败不得静默回退明文**；音频删除不宣称达到生产级安全擦除。
- **分层证据**：决策/待办逐条关联原话片段+匿名发言人+起止时间（无证据则待确认）；章节/发言人纪要关联代表性时间；全文纪要关联章节、不要求每句绑原话。

### 2.5 验收标准（§13，均"待执行"，非已通过）
- 功能验收 F-01~F-26（含 NPU 真机不得冒充、全文由章节汇总生成、加密失败不写明文、音频删后保留正式纪要等）。
- 内容验证只出**描述性结果+错误案例**（用录音1/录音2 官方 TextGrid/RTTM 参考，可报 CER/DER/错误案例但**不出通过/失败结论**）。
- **当前不设任何指标门槛**（CER/DER/决策精召/章节分割/时延/内存/功耗/G2/G3 全不冻结）。

### 2.6 非功能需求
隐私：全链路局域网闭环、不外发、状态可见；本地加密（算法/密钥/轮换 TBD，失败不回退明文）；音频独立删除+分对象删除状态。性能：120min 为输入上限目标，时延/内存/温度/功耗待压测、不承诺。存储：PC 存并播放原始音频，板端存处理临时副本。审计：删除/确认/修改/失败留最小审计。

## 3. PRD 演进脉络（发现 → v0.1 → v0.2 → MVP v1.0）

均生成于 2026-08-14。

- **发现阶段**：确立"逐字稿不是中心、决策/行动项/正式纪要才是"；16 项 P0 候选归入三质量门 **G1 安全授权 / G2 内容可信 / G3 正式闭环**，三门全过才算首版闭环。硬边界：无真实用户访谈、飞书样例无 Gold。
- **起草前决策记录**：最关键新增 **责任团队 vs 个人责任人分离建模**，解决"团队已明确、个人待指定"被误判为"无责任归属"的语义陷阱。
- **v0.1**：16 项 P0-C 重构为 **26 项可验证 P0-FR**（G1=001-009/G2=010-019/G3=020-026）；角色 8→**4 类最小角色**；防编造/证据降级三态。
- **v0.1 预评审**：七类角色 47 条问题，筛出 7 条纯产品规则问题进 v0.2。
- **v0.2**：合并八组规则决策（DEC-02-01~08）；新增"显式弃权""记录条目级责任人接受状态"；会尾按 **S(1-8)/M(9-20)/L(21+)** 人数分组，1–3 分钟仅限 S 组；26 项追踪矩阵=**23 硬门 / 2 允许降级 / 1 可后移**。
- **MVP v1.0**：从 v0.2 大幅裁剪为内部技术演示版——现场录音/大屏多人确认/USB-PDF/复杂角色全部延期或改写（大屏多人→PC 单人、USB PDF→本地三文件、G2/G3 质量门→描述性验证）。

### 4.3 诚实边界 / TBD 雷区（写汇报或对外时必看）
1. **两代形态冲突**：MVP PRD 说"WAV-only、单任务、不做会议库/多格式"，但 **API 契约 v1.0 已含 SQLite 会议库、多格式上传、PC/板端录音**——契约走得比 MVP PRD 更远。口径：契约=目标态/当前基线，MVP 首轮只跑其子集。
2. **技术冻结口径**：MVP 反复说"模型/ASR/说话人版本待冻结"，但契约已写死 `qwen3-4b-v104-ctx16k` / `3D-Speaker/CAM++` / `Batch Qwen3-ASR`——以契约为当前基线，非最终冻结。
3. **量化指标是最大雷区**：需求假设里出现"决策准确率 100%""待办召回≥95%""3 分钟确认"等，但竞品总结/PRD 演进/MVP §13 **一致要求不得写成发布承诺**——只有"AI 编造为 0（无证据不进正式纪要）"作为**产品原则**保留，其余全 TBD。**两份文档都不要把这些数字写成已达成。**
4. **访谈是虚拟场景**、竞品**均未实测**——需求调研务必标"假设/待验证"，不可当真实客户/评测证据。
5. **未决项 U-001**：USB 是否附带原始音频/水印/有效期，从发现阶段到 v0.2 仍未决（MVP 已把 USB 整体延期）。
