## 阶段一 · LLM 基线与结构化输出（2026-07-28）

## 阶段二 · ASR 板端可行性（2026-07-29 ~ 08-05）

- 本地 **SenseVoiceSmall CPU** PASS：30s 片段、feature `[1,500,560]`、~1.09s。
- 板端 **SenseVoice RKNN3 失败**：模型 IO `[1,600,560]`→`ctc_logits[1,604,25055]`，推理 `encoder_out_lens=0`、CTC 全 blank、run≈2978ms。
- **定位**：官方 `rknn3_model_test.py` 复现同样失败（`ctc_logits` cosine≈0.951 但 output1 cosine=0）→ 排除自研 runner/传输/dtype，锁定 **模型导出/runtime 1.0.0/算子兼容性**。→ 转 **Qwen3-ASR**（RKNN3 v1.0.4）。
- Qwen3 lifelog 微调对比（07-29）：tuned merged `json_valid=true`、completion 433 tokens、quote 4/4；base 因 512 截断失败。

## 阶段四 · ASR 切片与批处理优化（2026-08-07 ~ 08-10）

- **切片**：引入「ASR unit」（合并同 speaker、短 fragment 作 bridge、不跨 boundary）→ 155 → 95 → **bridge4 87 chunk（−43.9%）**；bridge4 全量 87/87 成功、589.4s；时长主要落 15-30s（62/87）。
- **Batch 加速 A/B**（整场只加载一次、串行全 chunk、每 chunk 清 KV）：

| 规模 | 逐 chunk 重启 | Batch | 加速 |
|---|---:|---:|---:|
| 2 chunk | — | — | 1.83× |
| 12 chunk | 80.6s | 14.2s | 5.68× |
| **87 chunk（全量）** | **587.8s** | **66.0s** | **8.91×（省 88.8%）** |

- 87/87 逐字一致（`transcript_equal=True`），正/逆序结果一致（无跨 chunk 污染）。ASR 释放 NPU 后 Qwen3-4B 18s 就绪。

## 阶段八 · 结构化日志 / 可观测性迁移（2026-08-24 ~ 09-01）

依据 `2026-08-24_结构化日志迁移执行计划.md`，把诊断从「文本日志 + 事后猜测」迁移为**机器可读 sidecar = 唯一诊断事实源**（工程/可观测性里程碑，非模型实验）。这是后续所有"可归因"实验的地基。下面落地情况经 **2026-09-11 逐条对照源码核实**（非按计划假设）。

- **改造范围（P0–P8）**：P0 固定代码源+manifest（SHA-256 消版本漂移）→ P1 修 `runlog` 底座 → P2 接入 `llm.py`（传输事实）/`product_summary.py`（业务校验事件）→ P3 Board Worker 优先读 canonical sidecar → P4 Board Agent bounded projection → P5 Gateway 产品层投影 → P6 本地单测+API smoke → P7 板端回归 → P8 旧日志降级。
- **sidecar 产物**：`run_manifest.json / run_events.jsonl / run_metrics.json / error_report.json / stage_status.json`（+ `03_llm_summary/requests/`）。
- **关键设计**：统一身份 `trace_id/meeting_id/task_id/run_id/source_sha256`；UTC `Z` 时间；`return_code` 统一；重试语义拆 `technical_retryable/product_retryable/retry_scope`；三层脱敏（绝对路径/prompt/模型原文/音频/完整堆栈不外传）。
- **✅ 确凿落地（有测试）**：**P1**（五件 sidecar / UTC-Z / 四段 identity / technical+product 双重试标志）、**P2**（`llm.py` 传输事件+响应字段、`product_summary.py` 五业务事件且逐 attempt 记录）、**P3**（Worker canonical 读取 + `legacy` fallback）、**P5**（Gateway 优先链 + `diagnostic_source` 二分 + `include=diagnostics` 门控 + 路径净化）。测试：`tests/unit/observability/test_runlog.py`、`llm/test_request_logging.py`、`adapters/board/test_worker_sidecars.py`、`integration/test_p0_diagnostics.py` 等。
- **◻️ 偏差（诚实）**：P4 Board Agent 白名单+限幅有，但 **`schema_version` 仅透传未校验**；`return_code` 仅 canonical 路径统一，遗留 board 脚本仍用 `exit_code`；**`retry_scope` 是 Gateway 层概念、harness 不产出**；identity **不含 `source_sha256`**（哈希在 manifest/result）；product_summary 事件 / board_agent 投影**缺独立单测**（仅集成测试间接覆盖）。
- **❌ 无代码证据**：P7（板端完整回归）/ P8（旧日志降级）未见明确对应物，不作完成结论。
- **意义**：阶段九 5 组的 `run_report/stage_status/loaded_once`、以及端到端（阶段十三）的诊断投影，全部建立在这层 sidecar 之上。

## 阶段十二 · 4B 摘要微调实验（2026-09，诚实负结果）

- 全链路：train_S 8 场 → A0 分块 44 块 → 教师蒸馏 → QLoRA（loss 1.91→0.83）→ held-out 评测。
- **核心事实召回 BASE 0.167 → TUNED 0.024（Δ=−0.143，负结果）**。
- 归因：8G 显存逼数据滤到 17 对 + 推理截断 3072（评测被污染）+ 架构已用脚手架绕开 4B 归纳弱项。**不粉饰为提升**；若认真做需 ≥12–24G 卡 + 更多蒸馏数据 + 少 epoch。

## 附：跨阶段结论

1. **端到端错误的头号来源是前端 VAD 丢语音**（点4 删除主导），不是聚类、不是 ASR 听错——这决定了本轮优先修 VAD 而非热词/微调。
2. **4B 的病在"漏"不在"编"**：over_decision=0 是唯一稳定强项，但发言人/低频/归纳召回弱（TextGrid 待办幻觉、发言人 66.7%）——架构用确定性骨架 + 受控抽取正是对症。
3. **工程优化收益明确**：ASR Batch 8.91×、VAD 整句丢 −68%；**微调收益为负**（8G 约束）。
