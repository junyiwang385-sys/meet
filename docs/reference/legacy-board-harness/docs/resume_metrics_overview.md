# 简历评测指标说明

本文用于简历和面试准备，说明基于 AISHELL-4 中 103 组真实多说话人会议音频建立的端到端质量评测指标。当前简历建议使用四个指标，其中核心内容覆盖率的“约 80%”是待专项抽样验证后的建议口径。

## 一、指标总览

| 指标 | 当前结果 | 说明 |
| --- | ---: | --- |
| 语音活动检测 F1 | 94% | 语音区间是否切得完整、准确 |
| 说话人聚类准确率 | 97% | 已识别语音的说话人归属是否正确 |
| 摘要事实忠实度 Faithfulness | 91% | 摘要中写出的事实是否有参考依据 |
| 核心内容覆盖率 | 约 80%* | 会议中的重要内容是否被摘要覆盖 |

详细结果：

```text
Speech precision：90%
Speech recall：100%
Speech F1：94%
Speaker clustering accuracy：97%
Faithfulness：91%
Core content coverage：约 80%*
```

\* 核心内容覆盖率目前是建议简历口径，正式数值需要在新版 expected 和 Judge 流程上完成专项抽样验证后确定。

---

## 二、语音活动检测 F1

### 1. 它衡量什么

把官方 TextGrid 中的人工语音标注作为真实结果，把系统切出的语音片段作为预测结果，比较两者在时间上的重叠程度。

这个指标衡量的是“语音区间切得好不好”，不是 ASR 文字识别准确率，也不是 Pipeline 是否成功运行。

### 2. 计算公式

```text
Precision = 重叠的语音时长 / 系统预测的语音时长

Recall = 重叠的语音时长 / 标注中的真实语音时长

F1 = 2 × Precision × Recall / (Precision + Recall)
```

当前结果：

```text
Precision = 90%
Recall    = 100%
F1        = 94%
```

### 3. 如何解释

- Recall 100%：标注中的语音基本没有被系统漏掉；
- Precision 90%：系统预测的语音区间中，约 90% 得到了人工标注支持；
- F1 94%：系统在“不漏语音”和“减少额外语音区间”之间取得了较好的平衡。

当前系统采用偏 recall-first 的策略，优先保证不漏掉会议语音，因此 precision 会相对低一些。

### 4. 面试时怎么说

> 我们以官方 TextGrid 作为语音活动真值，把系统输出的语音片段与人工标注进行时间重叠比较，计算 speech precision、recall 和 F1。103 组真实会议音频上 recall 达到 100%，precision 为 90%，F1 为 94%，说明系统优先保证语音覆盖完整，同时控制额外的误报区间。

### 5. 注意

这个指标是语音活动检测指标，不能直接称为标准 DER。它只反映语音区间覆盖，不反映文字识别或说话人归属。

## 三、说话人聚类准确率

### 1. 它衡量什么

它衡量系统是否把语音正确分到了对应的说话人簇中。

预测结果和人工标注中的说话人编号都是匿名的，例如预测结果可能是 `speaker_0`，人工标注可能是 `002-F`。编号名称不同并不代表归属错误，所以不能直接比较字符串。

### 2. 计算方法

先根据预测结果和人工标注的时间重叠关系，使用 Hungarian algorithm 做预测说话人和参考说话人的最优一对一匹配；然后按 100 ms 的时间帧比较两边的说话人归属。

```text
Speaker clustering accuracy
= 归属正确的有效时间帧数 / 有效时间帧总数
```

当前结果：

```text
Speaker clustering accuracy = 97%
```

这里的“有效时间帧”指参考侧有说话人、预测侧也有已知说话人归属的时间帧。这个指标不等同于标准 DER，简历上建议写“说话人聚类准确率”，不要写成“说话人识别准确率”。

### 3. 如何解释

97% 表示：在已经归入已知说话人簇、并且满足评估条件的时间帧中，系统的说话人归属与人工标注高度一致。

它主要体现的是说话人聚类和归属能力，不代表系统已经识别出了说话人的真实姓名或身份。

### 4. 面试时怎么说

> 由于预测和人工标注的 speaker ID 都是匿名的，我先根据时间重叠计算最优的一对一标签映射，再按 100 ms 时间帧比较说话人归属。103 组真实会议音频上，映射后的说话人聚类准确率为 97%。这个指标反映的是匿名说话人聚类质量，不直接等同于标准 DER。

## 四、摘要事实忠实度 Faithfulness

### 1. 它衡量什么

Faithfulness 衡量摘要中已经写出来的事实，是否能在官方 Reference Timeline 中找到依据。

它回答的是：

```text
摘要写出来的内容有没有事实依据？
```

它不衡量摘要漏掉了多少内容；遗漏重点属于 completeness 问题。

### 2. 计算方法

评测模型从摘要中的全文概述、章节摘要、发言人摘要和待办事项中提取一条条可验证的事实，然后逐条与 Reference Timeline 对照。

每条事实分为四种情况：

- `supported`：参考内容完全支持，计 1 分；
- `partially_supported`：主要意思正确，但范围、语气或细节有偏差，计 0.5 分；
- `unsupported`：参考内容没有足够依据，计 0 分；
- `contradiction`：与参考内容发生冲突，计 0 分。

### 3. 计算公式

```text
Faithfulness
= (supported 数量 + 0.5 × partially_supported 数量)
  / 全部可验证事实数量
```

Faithfulness 不按事实的 minor、major、critical 等级加权，每条事实按同样的基础权重计算。

当前 103 组结果：

```text
Faithfulness = 91%
```

### 4. 如何区分几种状态

```text
Reference 没有足够依据，但也没有明确反驳
→ unsupported

Reference 明确显示摘要说错了，或 speaker、数字、结论发生冲突
→ contradiction
```

例如：

- “会议讨论了车辆管理”，Reference 中有对应内容：`supported`；
- “会议形成了宠物管理解决方案”，但 Reference 只支持部分建议：`partially_supported`；
- “会议提出了维护控制方案”，Reference 中没有对应事实：`unsupported`；
- 把讨论中的意见写成已经确定的决定，或把事实归给错误的说话人：`contradiction`。

### 5. 面试时怎么说

> 我们把官方 TextGrid 转换出的 Reference Timeline 作为事实依据，对摘要中的事实进行逐条判断。每条事实分为 supported、partially supported、unsupported 和 contradiction，分别按 1、0.5、0、0 计分，最终得到 Faithfulness。103 组真实会议音频上的事实忠实度为 91%，主要用于衡量摘要是否出现事实错误、错误归因，或者把讨论内容写成已经确定的决定。

## 五、核心内容覆盖率

### 1. 它衡量什么

核心内容覆盖率衡量会议中真正重要的内容，有多少被候选摘要覆盖到了。

它回答的是：

```text
会议中的主要议题、关键结论、明确行动和重要风险，是否被摘要总结出来？
```

它与 Faithfulness 关注的方向不同：

```text
Faithfulness
→ 摘要写出来的内容是否有事实依据

核心内容覆盖率
→ 会议中重要的内容是否被摘要覆盖
```

### 2. 核心事实如何确定

评测前先根据官方 Reference Timeline 整理每场会议的 `core_facts`，数量由会议复杂度和独立核心事实的实际数量决定，不设固定条数；技术上限为 30 条。核心事实主要包括：

- 主要议题；
- 重要结论或决定；
- 明确要求执行的行动；
- 重要风险、限制或未决问题。

每条核心事实都必须是原子、可独立判断的内容，并且有 Reference Timeline 中能够直接支持它的片段。核心事实标签属于基于官方 Timeline 整理的 LLM-assisted labels，Reference Timeline 仍然是最终事实依据。

### 3. 计算方法

Judge 逐条判断候选摘要是否覆盖每个核心事实：

- `covered`：正确表达核心事实，计 1 分；
- `partial`：表达了主要意思，但遗漏重要限定，计 0.5 分；
- `missing`：没有覆盖，计 0 分。

核心事实按重要性加权：

- `major`：权重 2；
- `critical`：权重 3。

计算公式：

```text
核心内容覆盖率
= Σ（核心事实权重 × 覆盖系数）
  / Σ核心事实权重
```

Candidate 的 overview、chapters、speakers 或 action_items 任一部分覆盖核心事实都可以计分，同一条事实只计算一次。action_items 仍然单独检查 owner、deadline 和任务真实性，但不能因为 owner 或 deadline 未明确就扣除整条核心事实。

### 4. 当前建议口径

核心内容覆盖率目前建议在简历上写成：

```text
核心内容覆盖率约 80%
```

这个数值适合作为当前简历的预留口径：75%～85%通常是较可信的结果区间，90%以上需要更充分的多组数据支撑。由于目前尚未使用新版 `core_facts` expected 完成专项抽样验证，正式结果确定后应以实际测量值替换“约 80%”。

### 5. 面试时怎么说

> 除了 Faithfulness，我还设计了核心内容覆盖率，用来衡量摘要是否抓住了会议重点。我们先从官方 Reference Timeline 中整理主要议题、关键结论、明确行动、风险和未决问题等核心事实，再由 Judge 逐条判断摘要覆盖情况，并按照事实重要性进行加权。它与 Faithfulness 互补：Faithfulness 关注“写出来的内容对不对”，核心内容覆盖率关注“重要内容有没有漏掉”。

## 六、四个指标合起来说明什么

```text
语音活动检测 F1
→ 语音区间切得是否完整、准确

说话人聚类准确率
→ 语音是否归到了正确的说话人簇

Faithfulness
→ 摘要写出的事实是否可靠

核心内容覆盖率
→ 摘要是否覆盖了会议重点
```

它们分别对应会议系统的三个阶段和摘要质量的两个维度：

```text
语音区间 → 说话人归属 → 摘要事实
```

## 七、面试综合表述

> 我针对真实多说话人会议音频建立了分层质量评测。首先，以官方 TextGrid 为语音真值，计算语音活动检测的 precision、recall 和 F1，103 组数据上 recall 为 100%，precision 为 90%，F1 为 94%。其次，由于预测和人工标注的 speaker ID 都是匿名的，我先做最优标签映射，再按 100 ms 时间帧计算说话人聚类准确率，结果为 97%。最后，以 Reference Timeline 为事实依据，从 Faithfulness 和核心内容覆盖率两个维度评估会议摘要：Faithfulness 91% 用于衡量摘要写出的事实是否有依据，核心内容覆盖率约 80% 用于衡量会议重点是否被覆盖。
