## 一、Harness 框架工程

### 1.1 结构化日志 / 可观测性(`observability/`)
- **sidecar JSONL 日志**(`runlog.py` `RunLogContext`):单次运行的结构化事件流,与主结果分离落盘。
- **运行指标**(`metrics.py` `RUN_METRICS`)、**诊断报告**(`error_report.py`):失败时产出小型诊断。
- **隐私红线**:`error_report` **不嵌入 prompt / 模型输出**(`build diagnostic without embedding prompts or model output`);诊断链 sidecar→worker→board→gateway 全程不泄漏 prompt/content(有集成测试 `test_p0_diagnostics` 守)。
- **identity 贯穿**(`contracts/identity.py` `RunIdentity`):runlog / metrics / error_report **共享同一 identity**,可交叉关联。
- **schema 独立演进**:sidecar 的 `schema_version` 与主 Harness result schema **独立版本**,互不绑死。
- **run_report**:从 manifest 出报告——`server.loaded_once`(模型是否只加载一次)、token 经济学、红旗;阶段级 `stage_status.json` 6 阶段 succeeded。

### 1.2 断点恢复 / 崩溃安全(详见 `docs/断点续跑机制.md`)
- **三级 checkpoint**:
  - **阶段级**:`stage_status.json` + `resolve_first_unfinished_stage`,从第一个未完成阶段续;
  - **LLM 请求级**:每个请求落 5 产物,复用需**六重全过**(文件齐 + fingerprint 匹配 + 各产物 sha256 对 + finish_reason=stop 未截断 + validation=pass + 重跑校验一致);
  - **ASR 块级**:按音频块缓存,跳过已转写。
- **原子写**(`storage/artifacts.py`):`tmp→fsync→os.replace`,断电写一半也不损坏 checkpoint(续跑地基)。
- **粒度极限(诚实)**:单次 LLM 生成半途崩→整条请求重跑,**不能续 token**;配置变则 `verify_resume_snapshot` 拒绝复用。

### 1.3 契约
- `PipelineStageError.return_code` 契约;compact refs(r*/sp*)↔canonical(seg-*/speaker_*)payload 压缩/展开。

## 二、小模型可靠性工程(核心护城河)

### 2.1 能力边界(PC 实测 + 论文)
4B **强**:检索(RULER-lite 8k 内 100%)/聚合/判断/受控抽取;**弱**(≤30%):自主归纳/篇章分章/低频数字;**病在漏不在编**(但自由生成会造字)。

### 2.2 九条设计原则(围绕边界,`CLAUDE.md`)
确定性 DAG 搭骨架(切分/去重/边界算法定,不让 4B 自主决策)→ 自主归纳降级为**受控抽取**(extract-then-compose)→ 一次一任务不复合 → carryover 用**压缩摘要不给原文**(防串味)→ 全局靠显式构造(主题词/reduce)→ 强 schema + 规则**不用 few-shot**(弱模型会 echo)→ **分层**:无损前置喂下游、有损顺滑只展示、refs 锚 L1 原文 → 提示词/规则针对**类别/构词**不针对实例(领域走 profile)。

### 2.3 优雅降级(宁可产出,别整场崩;本轮补齐)
扩样本暴露并**治本四类块阶段崩溃**:
- 巨块 `length`→`max_block_segments=60` 二道尺寸闸 + 合并守卫;
- 薄块 `too short`→内容感知长度门(薄源块降门槛);
- 缺字段 `missing title` 等任意块崩→**块级降级**`_fallback_block_summary`(退确定性抽取式);
- 概览退化 `overview short`→**概览级降级**`_fallback_overview`(从已校验章节拼)。
30 场跑批中 7/30 触发降级、整场未崩(对应组件是抽取式底线,已诚实标注)。

### 2.4 不编造底线(`validation.py`,~26 单测守)
owner 无据清空 / deadline 不在原文清空 / 跨发言人 refs 丢 / 无效·空文本 refs 丢 / 占位词→None / finish_reason·截断拒绝。**待办 recall 地板**:action-review 塌缩时退块级候选(`_actions_from_candidates`),不静默丢。

## 三、各模块选型(依据分级,详见 `docs/选型依据审计.md`)

| 模块 | 选型 | 依据类型 |
|---|---|---|
| 前端 VAD | fsmn-vad `thres 0.6→0.2` | **📊 评测驱动**(参数矩阵+全30场,整句丢 28%→9%) |
| 说话人分离 | 3D-Speaker CAM++ `win3/thr0.68` | 📊 9 组参数对比 |
| ASR | Qwen3-ASR(弃 SenseVoice)+ 热词偏置 | 排障实测(SenseVoice 板端出不了)+ B-WER 0.186→0.083 |
| 摘要主链路 | Qwen3-4B map-reduce 滑动章节 A0 | 🧭 能力边界驱动(4B 复合长会崩+归纳弱);A0 召回 0.43→0.64 |
| carryover | 压缩摘要,不给前文原文 | 📊 串味实测 |
| 提示词 | 强 system 约束,不用 few-shot | 🧭 echo 踩坑 3 次 |
| 4B 微调 | **弃(负结果)** | 📊 held-out 召回 0.167→0.024 |
| 框架选型(3D-Speaker/fsmn/Qwen3-ASR) | RKNN3 生态可得 + 能跑 | ⚙️ **可得性/未横评**(诚实:非同任务对比) |
| beam search | 不做 | ⚙️ 端侧多份 KV 亏内存的推断 |

> 分级(诚实):📊 评测驱动 / 🧭 能力边界机理 / ⚙️ 可得性惯例未评测。**"参数怎么调/方案哪个好/要不要做"多有据;"选哪个框架"层面是可得性+边界,未做横评。**

## 四、测评(三层栈 · 三方分离 · 详见 `eval/评测框架总览.md`)

### 4.1 体系
- **三层栈**:L1 确定性主判据 / L2 校准后 LLM 裁判(≥0.8 一致率才采信)/ L3 两两盲评(未落地)。
- **三方分离**:候选=4B / 金标=fable5 生成+opus5 核验的**银标**(30 场)/ 裁判=opus。
- **一键入口** `run_all.py` → `RESULTS_main`;裁判默认本地 Ollama(无 key)、决策符合度用 opus。
- **DeepEval 定位**:可选 CI 皮(6/62 文件),核心是自建确定性评测。

### 4.2 结果(干净线 n=30)
| 层 | 指标 | 结果 |
|---|---|---|
| 摘要维度(确定性) | core召回 / 决策覆盖 / 待办覆盖 / 金句逐字 | 0.82 / 0.91 / 0.93 / 0.85 |
| L1 确定性(门禁) | 锚点支持 / 关键词纯净 / owner归属 | 1.0 / 1.0 / 0.14 |
| 决策符合度(opus n=30) | 忠实度 / over_decision / missed / critical | 0.87 / **5.0/场** / 0.53/场 / 2.0/场 |

**读**:内容覆盖/召回强、证据可追溯满分、决定捕获完整(missed 低);但 **over_decision 5/场(0 场为 0)**——"决策不升格"卖点在 n=30 **不成立**,+ critical 2/场(编造)。**A0 从 board 的"保守漏决定"摆到"激进升格提议"。**

### 4.3 诚实边界
PC 等价替代非板端复现(~5% 差)· 银标非人工 gold · 决策符合度是 opus 裁判(校准后趋势,不设硬门禁,有波动)· 长会 1-2h 完全未验 · 转写/分章线未并入本次主报告。

### 4.4 最有价值的结论
**评测框架用 n=30 opus 裁判,量化并推翻了小样本(n=2)得出的头号卖点(over_decision=0)**——发现问题的能力 > 虚假卖点。
