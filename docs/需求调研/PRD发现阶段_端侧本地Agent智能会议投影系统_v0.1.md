## 1. 文档目的与当前阶段

### 1.1 文档目的

本文件用于在正式编写PRD v0.1前，形成一套可审阅的产品发现基线：

1. 明确产品试图解决的问题；
2. 明确目标用户和会议场景假设；
3. 明确端到端用户流程；
4. 明确候选P0、P1、P2范围及P0非目标；
5. 明确信息结构、证据关联和正式纪要状态；
6. 明确本地处理、安全、录音授权、删除和导出边界；
7. 提出候选验收目标及其验证方式；
8. 区分哪些内容可进入PRD初稿，哪些仍被用户、Gold、设备或安全验证阻塞。

## 4. 产品定位与差异化方向

### 4.1 候选产品定位

> **面向敏感企业固定会议室的端侧会议执行与治理终端：在明确授权下，于客户控制环境内完成会议理解，在会尾帮助参会者共同确认决策和行动项，并形成可追溯、可治理、可受控流转的正式纪要。**【产品分析】【需求假设，待真实用户验证】

### 4.2 候选差异化主轴

| 差异化主轴 | 候选产品含义 | 证据性质 |
|---|---|---|
| 本地安全处理 | 核心会议内容不依赖外部公共云即可完成采集、理解、确认和保存 | 【产品分析】【端侧能力，待设备验证】 |
| 会尾共同确认 | 用共享大屏集中核对决策、行动项、缺失字段和未解决问题 | 【竞品证据】【产品分析】【需求假设，待真实用户验证】 |
| 行动项闭环 | 分离任务、责任人、截止时间、验收标准、依赖和执行状态 | 【脚本级Gold规则】【产品分析】 |
| 证据可追溯 | 每条关键结果关联原话、说话人、时间范围和音频定位 | 【竞品证据】【脚本级Gold规则】【产品分析】 |
| 正式纪要治理 | AI草稿经授权人员确认后才成为正式版本，修订形成新版本 | 【产品分析】 |
| 分层生命周期 | 音频、转写、草稿、正式纪要、证据和审计记录分别保存或删除 | 【安全或生命周期要求，待评审】 |

### 4.3 与现有产品形态的边界

- 不与云端竞品正面竞争公共链接、评论、跨组织协作和通用知识库能力。【产品分析】
- 不把会议室大屏、摄像头跟踪或麦克风规格等同于会议理解和正式纪要能力。【竞品证据】
- 不把时间轴、章节和回放等同于每条结构化结论的独立证据链。【竞品证据】
- 不把存在任务系统接口等同于AI提取、人工确认、任务创建和状态回写闭环。【竞品证据】
- 不把“本地模型”宣传等同于完整数据路径已经验证。【产品分析】【端侧能力，待设备验证】

| 语言 | 普通话为主 | 【需求假设，待真实用户验证】 |

| 使用频率 | 每周多次项目、评审或管理会议 | 【需求假设，待真实用户验证】 |

### 5.2 角色假设

| 角色 | 候选用户 | 核心工作 | 主要价值假设 |
|---|---|---|---|
| 会议主持人／项目负责人 | 项目经理、研发负责人、部门负责人 | 推动会议、确认决策、分配任务 | 减少会后整理和争议，快速形成执行依据【需求假设，待真实用户验证】 |
| 纪要编辑者 | 秘书、助理、项目运营人员 | 修正文字、结构和责任字段 | 缩短整理时间并保留证据【需求假设，待真实用户验证】 |
| 普通参会者／任务责任人 | 研发、测试、制造、供应链人员 | 核对结论和自己的任务 | 减少责任和时间理解偏差【需求假设，待真实用户验证】 |
| 设备／系统管理员 | IT、信息化、会议室管理员 | 配置设备、账号、网络和保留策略 | 获得可部署、可维护、可审计的本地方案【需求假设，待真实用户验证】 |
| 安全把关者 | 信息安全、法务、合规人员 | 审核数据路径、权限、删除和导出 | 控制会议内容外流和生命周期【需求假设，待真实用户验证】 |
| 采购决策者 | 行政、IT、业务部门负责人 | 评估成本、部署和采购价值 | 获得区别于云端订阅和普通会议硬件的采购理由【需求假设，待真实用户验证】 |

### 5.3 核心会议场景假设

1. 项目周会和里程碑评审；
2. 研发设计评审；
3. 质量、生产和供应链协调会；
4. 客户需求与技术方案评审；
5. 内部经营复盘和管理会议；
6. 合同、招投标及技术方案讨论。

以上场景均为【需求假设，待真实用户验证】。

### 5.4 暂不优先场景

- 完全禁止录音的会议；
- 最高涉密等级会议；
- 超大会议室、公开论坛和大型活动；
- 高比例跨语言、同声翻译会议；
- 严重重叠发言、无固定座位和复杂远场场景；
- 家庭和低频个人使用。

上述范围控制属于【产品分析】，并非对市场规模的最终判断。

## 8. 会前、会中、会尾确认、会后管理的端到端流程

### 8.1 候选主流程

```text
会前配置与授权
  → 本地录音与会议理解
  → 停止录音并生成AI草稿
  → 会尾大屏共同核对
  → 主持人或授权人员确认
  → 生成正式纪要版本
  → 原始音频保留或独立删除
  → 本地加密保存或受控导出
  → 后续修订生成新版本
```

该流程属于【产品分析】，需要用户可用性、端侧能力和安全评审共同验证。

### 8.2 分阶段流程

| 阶段 | 用户动作 | 系统候选行为 | 阶段退出条件 | 证据性质 |
|---|---|---|---|---|
| 会前 | 选择会议、主持人、参会人、保密等级和数据策略 | 显示联网状态、处理位置、录音授权、剩余存储和麦克风状态 | 授权完成且设备可录音 | 【产品分析】【安全或生命周期要求，待评审】 |
| 会中 | 开始、暂停、静音、继续或停止录音；可手动标记决策/任务 | 本地录音、普通话转写、说话人分段、草稿提取和证据缓存；状态持续可见 | 主持人停止录音 | 【产品分析】【端侧能力，待设备验证】 |
| 会尾准备 | 等待草稿完成，选择进入确认 | 聚合决策、任务、依赖、未解决问题和风险；突出缺失字段 | 草稿达到可展示状态 | 【产品分析】【质量目标，待Gold验证】 |
| 会尾确认 | 参会者核对，主持人修改、补全、删除、合并或保留待确认项 | 支持条目直达原话；记录修改；防止无证据自动补全 | 授权确认人确认，或选择稍后确认 | 【脚本级Gold规则】【产品分析】 |

### 8.3 会尾未完成时

- 没有授权确认人时，纪要保持“待确认”，不得自动正式发布。【产品分析】
- 关键任务责任人或截止时间缺失时，条目保持“待确认”；如果主持人选择结束，可移入“遗留问题”，不能作为字段完整的已确认任务。【脚本级Gold规则】【产品分析】
- 发生争议时，应保留多个原话证据并将条目转为未解决问题，不由AI裁决。【产品分析】
- 草稿处理未完成时，可以稍后确认，但必须明确当前不是正式纪要。【产品分析】

### 11.2 字段语义规则

1. **决策**：只有明确达成的结论才能进入决策候选；建议、偏好、讨论和被否定方案不得写成决策。【脚本级Gold规则】
2. **任务**：至少有明确动作；责任人或截止时间可以缺失，但必须醒目标记。【脚本级Gold规则】
3. **责任人**：只能来自明确指派、自我承诺或会尾人工补充；不能因为某人提出任务就推断为责任人。【脚本级Gold规则】
4. **截止时间**：保留原始表达；只有语义无歧义时才规范化。没有企业规则时，“下班前”不得自动转换成18:00。【脚本级Gold规则】
5. **依赖项**：与任务单独建模；依赖未到位不等于任务取消。【脚本级Gold规则】
6. **未解决问题**：保留未决状态；不能因“需要确认”自动生成责任人和期限。【脚本级Gold规则】
7. **纠正**：最终有效值覆盖展示值，旧值保留在修改或证据记录中。【脚本级Gold规则】
8. **缺失值**：使用空值＋状态枚举，如“待指定、待确定、待核验”，不得使用模型猜测值。【脚本级Gold规则】
9. **结构合法性**：JSON/schema通过只是必要条件，不代表语义正确、无遗漏或无编造。【产品分析】

1. 每项正式决策和已确认行动项至少关联一组原始证据。【产品分析】

5. 没有可靠证据时，条目标记“待核验”，不得生成看似完整的引用。【脚本级Gold规则】

7. 证据定位需同时支持原文查看和音频回放；只有时间轴入口不算条目级证据闭环。【竞品证据】【产品分析】
8. 大屏默认显示最小必要原话，完整逐字稿按权限展开。【安全或生命周期要求，待评审】

### 12.3 原始音频删除后的证据降级

候选规则：【产品分析】【安全或生命周期要求，待评审】

- 原始音频存在：证据状态为“原文＋音频可核验”；
- 音频已删除但转写保留：证据状态变为“仅转写可核验”；
- 音频和转写均删除：正式纪要仍可保留，但证据状态明确显示“原始证据已按策略删除”；

- 正式纪要中应记录音频处理决定和删除时间；
- 是否保留音频哈希、删除证明或摘要指纹，需安全评审，不在本阶段冻结。

## 13. AI草稿、待确认、正式纪要、已修订和已删除等状态模型

### 13.1 纪要内容状态模型

```text
AI草稿
  → 待确认
    → 正式纪要
      → 修订草稿
        → 待确认
          → 已修订（新正式版本）

AI草稿／待确认／正式纪要／已修订
  → 已删除（按权限和策略）
```

`已发布／受控分发`建议作为分发状态，而不是替代内容状态；同一正式版本可以未分发、已分发或已撤回。【产品分析】

### 13.2 状态定义

| 状态 | 定义 | 可作为执行依据 | 允许的主要操作 | 必要记录 |
|---|---|---:|---|---|
| AI草稿 | 系统自动生成，尚无人审核 | 否 | 查看、重新生成、进入确认、删除 | 模型/版本、生成时间、来源会议 |
| 待确认 | 主持人或参会者正在核对，缺失项和争议可保留 | 否 | 编辑、看证据、补字段、转遗留问题、确认或放弃 | 编辑人、修改差异、待确认项 |
| 正式纪要 | 授权人员确认的首个正式版本 | 是 | 查看、受控分发、发起修订、按策略删除 | 确认人、确认时间、版本、分发范围、音频决定 |
| 修订草稿 | 基于正式版本发起的修改中版本 | 否 | 编辑、看差异、提交确认或取消 | 父版本、发起人、修订原因 |
| 已修订 | 新版本已确认，旧正式版本保留历史状态 | 是，以最新有效版本为准 | 查看版本链、分发、再次修订 | 新确认记录、父版本、差异 |
| 已删除 | 内容对象按权限和策略不可再普通访问 | 否 | 查看删除审计；是否可恢复由策略决定 | 删除人、时间、原因、删除范围和验证结果 |

所有状态定义均为【产品分析】，需要法务、安全和用户流程评审。

### 13.3 关键转换保护条件

| 转换 | 候选保护条件 |
|---|---|
| AI草稿 → 待确认 | 草稿生成完成；显示证据和不确定项；确认人身份可用 |
| 待确认 → 正式纪要 | 授权确认人确认；关键决策有证据；字段缺失已补全或被明确转为遗留问题；分发和音频策略已选择 |
| 正式纪要 → 修订草稿 | 有修订权限；填写修订原因；保留父版本 |
| 修订草稿 → 已修订 | 重新经过确认；生成新版本号和差异记录 |
| 任一状态 → 已删除 | 满足权限、保留策略和安全审批；记录删除对象和验证结果 |

### 13.4 录音状态模型

```text
未授权
  → 已授权／待录音
    → 录音中
      ↔ 静音／暂停
      → 已停止
        → 本地处理中
          → 草稿可确认
```

- 未授权不得进入录音中。【安全或生命周期要求，待评审】

- 录音、静音、暂停、停止和处理状态必须持续可见。【产品分析】

### 13.5 数据对象状态模型

```text

             ↘ 删除失败／需处理
```

## 14. 会尾投影和共同确认流程

### 14.1 进入条件

- 录音已经停止，或主持人明确进入会尾确认模式；
- AI草稿已生成到可展示状态；
- 当前状态明确显示“AI草稿／待确认”；
- 主持人或授权确认人在场；
- 敏感内容展示范围符合会议权限。

以上属于【产品分析】，需真实用户和安全评审。

### 14.2 候选大屏信息布局

```text
顶部：会议名称｜录音已停止｜本地处理状态｜联网状态｜保密等级

左区：候选决策
中区：行动项（责任人、截止时间、依赖、验收标准）
右区：待确认问题、风险和分歧

每条：状态标签｜缺失字段｜原话证据入口｜编辑入口

底部：稍后确认｜返回修改｜确认并生成正式纪要
```

### 14.3 候选确认步骤

1. 系统先展示决策，不把普通讨论混入正式结果；
2. 主持人逐项确认、删除或转为待确认问题；
3. 系统展示行动项，责任人重点核对自己的任务；
4. 缺少责任人、截止时间或证据的条目醒目标记；
5. 点击条目查看对应原话、说话人和时间位置；
6. 时间纠正只展示最终有效值，并允许查看旧值和纠正证据；
7. 争议无法解决时转为未解决问题；
8. 确认人选择保密等级、分发范围和原始音频处理方式；
9. 执行“确认并生成正式纪要”，系统记录确认人、时间和版本。

步骤2～7受【脚本级Gold规则】约束；整体流程属于【产品分析】。

### 14.4 候选完成条件

- 所有正式决策均有明确语义和证据；
- 已确认任务具有责任人和截止时间，或被明确移入遗留问题；
- 未解决问题没有被写成正式决策；
- 缺失字段没有被AI补造；
- 确认人、确认时间和版本可记录；
- 音频处理和分发选择明确。

### 14.5 体验候选目标

- 会尾确认时长：候选目标1～3分钟，目标值待真实用户验证。【需求假设，待真实用户验证】

## 15. 本地处理、加密存储、原始音频独立删除和受控导出边界

### 15.1 “本地／客户控制环境”候选定义

候选P0定义：【产品分析】【安全或生命周期要求，待评审】

- 会议音频、转写、说话人、结构化结果和证据默认不发送到外部公共云；
- 核心闭环在断开公网时仍可运行；
- 如允许客户局域网服务器，必须明确其属于客户控制环境，并与外部厂商云区分；

- 所有外发路径必须有清单、策略和可见状态；

该定义必须由产品、安全、法务和目标客户共同确认，当前尚未冻结。

## 22. 是否满足进入PRD v0.1起草的结论

### 22.1 阶段结论

> **当前有条件满足进入PRD v0.1起草。**【产品分析】

理由：

- 产品问题、候选定位和差异化已经形成；
- 目标用户和场景假设已经明确标注，未冒充真实证据；
- 候选P0/P1/P2和非目标已经形成；
- 端到端流程、信息结构、证据、状态、会尾确认、安全和权限已有可供PRD展开的基线；
- MA-ACTION-001已定义行动闭环的脚本级语义标准；
- 所有质量、设备和生命周期缺口已显式列出。

### 22.2 进入条件矩阵

| 阶段 | 当前是否满足 | 说明 |
|---|:---:|---|
| PRD v0.1起草 | **有条件满足** | 以候选范围和待验证标签起草；先确认第21章关键产品决策 |
| P0范围冻结 | **不满足** | 缺真实用户访谈、会尾原型和初步可行性证据 |
| 质量指标冻结 | **不满足** | 缺真人录音、人工逐字稿、实际时间戳和扩展Gold |
| 端侧方案冻结 | **不满足** | 缺目标设备断网、性能、功耗、温度和稳定性实验 |
| 安全与生命周期承诺 | **不满足** | 缺威胁模型、加密、密钥、删除、保留和导出评审 |
| 最终硬件/量产规格 | **不满足** | 当前只有竞品形态参考，无本产品BOM和硬件验证 |
| 正式研发承诺 | **不满足** | P0、指标、架构、安全和采购价值均未完成冻结 |

### 22.3 进入P0冻结前仍需补齐的证据

1. **真实用户证据**：至少覆盖主持人/项目负责人、普通责任人、IT/会议室管理员、信息安全/法务和采购决策角色；验证问题频率、会尾接受度、本地价值、保留、导出和采购流程。【需求假设，待真实用户验证】
2. **实际录音Gold**：完成MA-ACTION-001真人录音、人工逐字稿、说话人和实际时间戳校准，并扩展不同会议表达。【质量目标，待Gold验证】
3. **端侧闭环证据**：断网完成录音、转写、结构化提取、证据、确认、保存和导出。【端侧能力，待设备验证】
4. **长会议和会议室证据**：30、60、120分钟资源、时延、功耗、温度、噪声、距离和多说话人测试。【端侧能力，待设备验证】
5. **会尾可用性证据**：验证1～3分钟候选目标、参与意愿、缺失字段处理和无触控操作方式。【需求假设，待真实用户验证】
6. **安全数据路径证据**：网络抓包、遥测、升级、日志和客户控制环境边界。【安全或生命周期要求，待评审】
7. **加密和密钥证据**：威胁模型、密钥存储、设备丢失、维修和恢复出厂方案。【安全或生命周期要求，待评审】
8. **生命周期证据**：音频、转写、草稿、正式纪要、证据和审计记录的独立保留、删除、恢复和销毁验证。【安全或生命周期要求，待评审】
9. **受控导出证据**：USB/LAN主路径选择、权限阻断、水印/有效期、失败处理和审计完整性。【安全或生命周期要求，待评审】
10. **产品载体和商业证据**：新投影、外接模块或会议终端的客户偏好、部署条件、BOM和可接受价格。【需求假设，待真实用户验证】【尚未确认】

### 22.4 最终发现结论

本产品具备进入PRD v0.1起草的结构化输入，但PRD必须继续保持“候选、假设、待验证”边界。当前最重要的不是继续增加功能，而是通过真实用户、实际音频Gold、端侧设备和安全生命周期验证，证明以下完整价值链能够成立：

```text
明确授权
  → 客户控制环境内处理
  → 可信结构化结果
  → 原话证据核验
  → 会尾共同确认
  → 正式纪要治理
  → 安全保存、删除和受控流转
```

在上述证据补齐前，不应冻结P0或做出正式研发、质量、硬件、采购和发布日期承诺。
