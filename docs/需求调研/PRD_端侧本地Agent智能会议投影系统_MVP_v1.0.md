## 2. MVP目标

### 2.1 唯一MVP目标

验证以下最小技术和交互闭环是否能够在开发板NPU与局域网PC环境中独立运行：

```text
PC选择本地中文WAV
  → 局域网发送到开发板
  → 开发板NPU完成转写、说话人、分章和纪要生成
  → PC分阶段展示处理结果
  → 用户查看证据并修正内容
  → 用户确认生成正式纪要
  → PC本地保存HTML、TXT和JSON
  → 原始音频可独立删除
```

### 2.2 MVP要回答的问题

1. 开发板NPU能否接收PC传入的单个WAV并完成一次完整处理链路？
2. PC端是否能清晰展示全文、章节、回放、发言人、决策和待办？
3. 大模型自主分章、章节总结和全文汇总的链路是否可用？
4. 用户是否能通过同步逐字稿、发言人、时间线和证据入口核对结果？
5. 用户是否能在不补造责任人、截止时间和证据的前提下修正并确认正式纪要？
6. 本地加密、音频独立删除和最小审计是否能够形成可观察的演示闭环？

### 2.3 MVP不回答的问题

- 产品是否有真实市场需求；
- 真实会议用户是否愿意在会尾确认；
- 模型整体准确率是否达到生产要求；
- 是否适合量产、客户交付或敏感会议部署；
- 最终硬件、模型、声学输入、成本和采购方案是什么。

## 3. 目标用户与首个场景

### 3.1 唯一MVP用户

**研发评审人员／演示操作人**。

该角色在内部技术演示中以“会议主持人／纪要确认人”的身份操作，但当前不实现真实身份认证，也不把输入的显示名等同于可信数字身份。

### 3.2 首个场景

> 研发评审人员在PC端选择一份本地中文WAV会议音频，系统通过局域网发送到开发板，由NPU完成处理。用户在PC端查看全文纪要、章节纪要、全文回放、发言人纪要、决策和待办；用户可以调整章节、修正发言人标签、修改结构化条目并查看证据；确认后生成正式纪要文件。

### 3.3 演示环境

| 项目 | MVP边界 |
|---|---|
| 前端 | PC端局域网Web界面 |
| Agent | 开发板NPU运行 |
| 网络 | PC与开发板局域网；运行时不依赖公网 |
| 输入 | 单个本地中文WAV |
| 处理 | 一次一个任务 |
| 音频 | PC保存并播放原始文件；开发板保存处理临时副本 |
| 输出 | 返回PC显示，并本地保存HTML、TXT、JSON |
| 演示数据 | 单独准备的非敏感演示样本 |
| UI参考 | 参考已有竞品调研中的内容组织和交互启发，不直接复制竞品能力或视觉资产 |

### 3.4 不作为MVP日常角色的对象

- 设备管理员；
- 普通参会者；
- 个人责任人；
- 安全审计员；
- 法务、采购或客户管理员。

这些角色可以在后续产品中重新设计，但不进入当前MVP的真实权限实现。

## 4. MVP范围

### 4.1 MVP必须实现

1. PC端局域网Web界面；
2. 全文纪要；
3. 章节纪要；
4. 全文回放，包含同步逐字稿、发言人和时间线；
5. 发言人纪要；
6. 决策与待办；
7. PC选择单个WAV，最长120分钟；
8. PC到开发板的局域网传输；
9. 开发板NPU处理；
10. 分阶段处理状态展示；
11. 自动分章、章节调整和重新生成；
12. 发言人标签最小修正；
13. 证据跳转；
14. 决策和待办人工新增、编辑、删除；
15. AI草稿与正式纪要分离；
16. 单一演示操作人整体确认；
17. 版本、确认和最小审计记录；
18. 本地加密存储；
19. 原始音频独立删除；
20. HTML、TXT和JSON正式纪要输出；
21. 取消、失败重试、局域网中断处理；
22. 待确认、缺失字段、冲突和证据不足状态。

### 4.2 后续版本延期

| 能力 | 延期原因 |
|---|---|
| 现场麦克风录音 | 当前MVP采用PC本地文件输入，先不接入采集链路 |
| 真实录音授权、撤回和物理静音 | 与现场采集和硬件链路绑定，不阻塞文件型技术演示 |
| 逐字稿人工修改 | 会引起时间戳、证据、章节和摘要级联更新 |
| 非WAV格式 | 增加解码、转码和声道适配范围 |
| 多任务、任务队列和断点续传 | 增加调度、恢复和资源隔离复杂度 |
| 多用户并发 | 当前只验证单一演示操作人 |
| 真实多角色权限和身份认证 | 不作为技术演示版的身份安全证明 |
| 遗留事项、开放问题、被否决方案和依赖的独立自动分类 | 当前只保留决策和待办独立结构化，其余进入待确认内容 |
| 个人责任人接受任务 | 当前不实现可信个人接受动作 |
| PDF、USB和外部受控分发 | 当前只在PC本地保存HTML、TXT和JSON |
| 跨会议任务跟踪和外部任务同步 | 超出单次会议技术演示闭环 |
| G2/G3自动评分、阈值和通过判断 | 当前只做功能和描述性验证 |
| 企业级密钥管理、密钥轮换和生产级安全擦除 | 当前只实现MVP本地加密和删除流程 |

### 4.3 当前明确不做

- 运行时调用公共云ASR、摘要或大模型；
- 真实敏感会议试点；
- 生产级安全认证、法律合规承诺或客户验收；
- 自动补造责任人、截止时间、部门、日期或证据；
- 将发言人标签自动解释为姓名、部门或责任关系；
- 通过模型输出替代官方TextGrid/RTTM证据；
- 将G3候选或单次演示结果写成最终语义Gold；
- 自动创建外部任务；
- 多租户、多组织和外部网络分发；
- 多语言、翻译、实时字幕、情绪分析、数字人和自动PPT。

## 6. 最小用户流程与异常流程

### 6.1 主流程

```text
打开PC端MVP演示页面
  → 创建单次演示会议
  → 选择本地WAV
  → 校验格式、时长和可读性
  → 显示PC—开发板局域网连接及“未使用公共云”状态
  → 发送到开发板
  → 开发板NPU处理
  → 先开放逐字稿、发言人和全文回放
  → 大模型自主分章并生成章节纪要
  → 根据章节纪要生成全文纪要和发言人纪要
  → 生成决策与待办候选
  → 进入AI草稿／待确认状态
  → 用户查看证据、调整章节和发言人、修改结构化条目
  → 用户整体确认
  → 生成正式纪要版本
  → PC保存HTML、TXT和JSON
  → 用户可独立删除原始音频
```

### 6.2 分阶段处理状态

```text
未选择音频
  → 已选择待处理
    → 正在发送到开发板
      → 开发板NPU处理中
        → 转写与发言人结果可查看
          → 章节纪要处理中
            → 全文／发言人／决策／待办处理中
              → AI草稿已生成
                → 可确认
```

失败分支：

```text
任一处理阶段
  → 处理失败
    → 显示失败阶段和原因
      → 从头重新处理
```

取消分支：

```text
发送中或处理中
  → 用户取消
    → 停止后续处理
      → 清理开发板临时副本
        → 不生成正式纪要
          → 可重新处理
```

### 6.3 内容状态

```text
AI草稿
  → 待确认
    → 正式纪要
      → 修订草稿
        → 待确认
          → 新正式版本
```

### 6.4 确认工作流子状态

| 子状态 | MVP语义 |
|---|---|
| `active` | 当前正在查看和修改草稿 |
| `deferred` | 用户暂不确认，草稿仍保留 |
| `overdue` | 如后续配置确认期限，仅表示超过期限，不自动正式化或删除 |
| `abandoned` | 用户放弃本次确认，不生成正式纪要，但不自动删除数据 |

### 6.5 异常流程

| 异常 | MVP处理 |
|---|---|
| WAV格式不支持 | 阻止处理，提示仅支持WAV及具体原因 |
| 文件超过120分钟 | 阻止处理，提示输入上限 |
| PC无法连接开发板 | 显示连接失败，不开始处理 |
| 局域网中断 | 当前任务失败，保留PC原始音频，从头重试，不支持断点续传 |
| NPU处理失败 | 显示失败阶段和原因，允许从头重试 |
| 用户取消 | 清理开发板临时副本，不生成正式纪要 |
| 转写或发言人不确定 | 使用匿名或`unknown`标签，不补造身份 |
| 模型无法确认 | 标记“待核验”，不生成确定值 |
| 责任团队缺失 | 字段为空或待确认，不从发言人或部门名称推断 |
| 个人责任人缺失 | 字段为空，不自动指定发言人或提议者 |
| 截止时间缺失 | 字段为空，不从相邻任务借用日期 |
| 结论冲突 | 保留冲突证据，进入待确认，不由模型强行裁决 |
| 用户放弃确认 | 标记`abandoned`，草稿和音频不自动删除 |
| 删除音频 | 删除PC原始文件和开发板临时副本，正式纪要保留，回放入口失效 |
| 删除失败 | 显示失败对象和原因，保留待处理状态，不宣称已完成 |
| 确认写入中断 | 不生成半成品正式版本，保留草稿和审计事件 |

## 8. 功能需求

> 本章的`MVP-FR-001`～`MVP-FR-023`均对应4.4节中的P0／MVP必须项。每项功能需求包含：需求ID、用户价值、功能描述、前置条件、主流程、异常流程、验收标准、依赖、证据状态和是否MVP必须项。4.4节补充每项需求的“实现建议（如何做）”。当前所有“端侧实现待验证”内容均不得写成已完成能力。

### MVP-FR-001｜PC端局域网Web演示入口

- **用户价值**：让研发评审人员在PC端完成整个MVP操作闭环。
- **功能描述**：提供局域网Web界面，包含全文纪要、章节纪要、全文回放、发言人纪要、决策与待办五个主要模块。
- **前置条件**：PC与开发板处于可通信的局域网；演示模式已启动。
- **主流程**：打开页面→创建单次会议→选择音频→查看处理结果。
- **异常流程**：页面无法访问或开发板不可达时显示明确错误。
- **验收标准**：无需公共云即可在PC端打开并完成一次演示任务；五个模块可访问。
- **依赖**：局域网服务、PC前端、开发板服务接口。
- **证据状态**：产品范围已确认；端侧实现待验证。
- **是否MVP必须项**：是。

### MVP-FR-002｜本地WAV选择与输入校验

- **用户价值**：让用户明确知道输入是否可处理，避免隐式转码或错误任务。
- **功能描述**：PC选择单个本地WAV；校验文件可读性、格式和最长120分钟限制。
- **前置条件**：本地存在可读取WAV；当前没有其他处理任务。
- **主流程**：选择文件→读取元数据→通过校验后显示文件信息。
- **异常流程**：格式不支持、文件损坏、时长超过120分钟或当前已有任务时阻止开始。
- **验收标准**：不符合条件的文件不会发送到开发板；错误信息可理解。
- **依赖**：WAV解析、单任务状态管理。
- **证据状态**：输入边界已确认；采样率、位深和声道的具体接口规格尚未冻结。
- **是否MVP必须项**：是。

### MVP-FR-003｜局域网传输与数据路径状态

- **用户价值**：让用户知道音频只在PC和开发板之间传输，不依赖公共云。
- **功能描述**：显示PC—开发板连接、发送、返回和“公共云未使用”状态。
- **前置条件**：局域网服务可用。
- **主流程**：文件校验通过→发送→显示传输状态→接收结果。
- **异常流程**：连接失败或连接中断时显示阶段、原因和重试入口。
- **验收标准**：演示中可观察到局域网闭环状态；无公共云调用链路。
- **依赖**：局域网协议、连接检测、接口清单。
- **证据状态**：产品边界已确认；数据路径和网络抓包待验证。
- **是否MVP必须项**：是。

### MVP-FR-004｜开发板NPU处理链路

- **用户价值**：验证端侧Agent不是预置结果展示，而是由开发板实际处理输入。
- **功能描述**：开发板接收WAV任务，执行转写、说话人、分章、总结和结构化提取，并返回阶段结果。
- **前置条件**：开发板模型和运行环境已准备；任务输入符合接口规格。
- **主流程**：接收任务→转写／说话人→章节总结→全文／发言人／决策／待办生成→返回结果。
- **异常流程**：模型加载失败、资源不足、超时或处理异常时返回失败阶段和错误信息。
- **验收标准**：至少使用一份非敏感演示WAV完成实际NPU处理；不使用预置最终结果冒充推理结果。
- **依赖**：模型、NPU运行时、输入接口、任务协议。
- **证据状态**：架构已确认；具体模型、版本、资源和性能待设备验证。
- **是否MVP必须项**：是。

### MVP-FR-005｜分阶段处理状态

- **用户价值**：降低长音频处理等待期间的不确定感。
- **功能描述**：显示选择、发送、NPU处理、转写可用、章节处理中、结构化处理中、草稿完成和失败状态。
- **前置条件**：处理任务已创建。
- **主流程**：按实际处理阶段更新状态；不显示无法证明的精确百分比。
- **异常流程**：阶段异常时停留在失败状态，不显示“已完成”。
- **验收标准**：用户能区分上传、NPU处理、结果返回和草稿完成。
- **依赖**：开发板阶段事件、PC状态机。
- **证据状态**：产品决策已确认；状态联调待验证。
- **是否MVP必须项**：是。

### MVP-FR-006｜取消、失败重试和单任务限制

- **用户价值**：避免长任务失败或无效等待时无法恢复。
- **功能描述**：一次只处理一个任务；处理期间允许取消；失败后允许从头重试。
- **前置条件**：存在上传中或处理中的任务。
- **主流程**：点击取消→停止后续处理→清理开发板临时副本；点击重试→从头发送和处理。
- **异常流程**：取消清理失败时显示待处理状态；不支持断点续传。
- **验收标准**：不会出现两个并行NPU任务；取消不生成正式纪要；失败可重新开始。
- **依赖**：任务状态、临时文件清理、NPU取消接口。
- **证据状态**：产品决策已确认；资源释放和清理待验证。
- **是否MVP必须项**：是。

### MVP-FR-007｜逐字稿、匿名发言人和时间线

- **用户价值**：让用户知道谁在什么时间说了什么，并可进行证据核对。
- **功能描述**：展示只读逐字稿、匿名发言人标签、起止时间和时间线。
- **前置条件**：ASR和说话人结果已返回。
- **主流程**：打开回放→逐字稿随播放高亮→显示当前发言人和时间。
- **异常流程**：说话人不确定时显示匿名或`unknown`；逐字稿缺失时显示不可用状态。
- **验收标准**：文本、发言人和时间可对应到同一音频时间轴；逐字稿不可直接编辑。
- **依赖**：ASR、说话人、时间戳、PC音频播放器。
- **证据状态**：功能范围已确认；ASR和说话人质量待Gold验证。
- **是否MVP必须项**：是。

### MVP-FR-008｜全文回放与证据跳转

- **用户价值**：让用户从纪要直接回到原话，降低人工寻找证据的成本。
- **功能描述**：支持播放、暂停、拖动、章节跳转、条目跳转和证据跳转。
- **前置条件**：PC仍保留原始音频；存在时间范围或音频位置。
- **主流程**：点击章节、决策、待办或证据→定位音频→同步高亮逐字稿。
- **异常流程**：源音频已删除时保留文本和证据时间，但禁用回放入口并显示原因。
- **验收标准**：章节、决策、待办和证据均可定位到对应时间范围；删除音频后状态正确降级。
- **依赖**：音频播放器、EvidenceLink、时间轴。
- **证据状态**：产品决策已确认；时间定位准确性待验证。
- **是否MVP必须项**：是。

### MVP-FR-009｜大模型自主分章与章节调整

- **用户价值**：自动形成会议结构，同时允许用户纠正明显错误的章节边界。
- **功能描述**：大模型自主判断章节边界并生成章节纪要；用户可改标题、合并、拆分和删除章节。
- **前置条件**：转写和时间线结果可用。
- **主流程**：模型分章→生成章节纪要→用户调整→重新生成受影响章节和全文纪要。
- **异常流程**：章节生成失败时保留转写和回放；不生成伪造章节。
- **验收标准**：至少能自动生成多个章节；合并／拆分后章节和全文内容更新；修改记录保留。
- **依赖**：大模型、章节对象、摘要重生成、版本记录。
- **证据状态**：产品决策已确认；分章质量待验证。
- **是否MVP必须项**：是。

### MVP-FR-010｜章节纪要到全文纪要

- **用户价值**：形成结构清晰、可阅读的整场会议总结。
- **功能描述**：先生成章节纪要，再根据全部最新章节纪要生成全文会议总结；全文纪要不是全文逐字稿。
- **前置条件**：章节生成完成；章节调整已处理。
- **主流程**：章节摘要→全文汇总→展示全文纪要；章节变化后重新汇总。
- **异常流程**：部分章节未完成时全文标记处理中，不允许正式确认。
- **验收标准**：全文纪要能够追溯到章节；不直接绕过章节从整场原始转写生成最终全文摘要。
- **依赖**：章节摘要、全文汇总模型、章节与全文关联。
- **证据状态**：产品决策已确认；摘要质量待验证。
- **是否MVP必须项**：是。

### MVP-FR-011｜发言人纪要和匿名标签修正

- **用户价值**：按发言人查看重点贡献，并纠正明显的说话人标签问题。
- **功能描述**：按匿名发言人汇总全场重点，关联章节和证据；允许修改显示标签、合并标签和标记`unknown`。
- **前置条件**：说话人结果和时间线可用。
- **主流程**：查看发言人纪要→修改标签或合并→重新生成受影响发言人纪要。
- **异常流程**：无法确认身份时保持匿名或`unknown`；不得推断姓名、部门或职位。
- **验收标准**：修改标签不改变原始说话人证据；发言人纪要可跳转到相关时间段。
- **依赖**：Speaker对象、说话人聚类、摘要重生成。
- **证据状态**：产品决策已确认；说话人质量待Gold验证。
- **是否MVP必须项**：是。

### MVP-FR-012｜决策提取

- **用户价值**：把已经形成的决定与普通讨论区分开，减少错误执行。
- **功能描述**：从章节和全文上下文中提取Decision候选；建议、偏好、普通讨论、被否定方案不得自动成为正式决策。
- **前置条件**：章节纪要和证据索引可用。
- **主流程**：生成决策候选→显示内容、证据、状态→用户确认、修改、删除或新增。
- **异常流程**：存在冲突或证据不足时进入待确认，不由模型强行选择。
- **验收标准**：决策具有内容、证据、发言人和时间范围；未经用户确认不进入正式纪要。
- **依赖**：Decision对象、EvidenceLink、弃权协议。
- **证据状态**：产品规则已确认；语义质量待验证，G3候选不得直接作为完成证明。
- **是否MVP必须项**：是。

### MVP-FR-013｜待办提取与责任字段

- **用户价值**：形成可核对的行动项，而不是泛化摘要。
- **功能描述**：提取ActionItem，至少包含内容、责任团队、个人责任人、责任状态、截止时间、证据和确认状态。
- **前置条件**：章节纪要和相关证据可用。
- **主流程**：生成待办候选→展示字段→用户补充或修正→确认纳入正式纪要。
- **异常流程**：团队明确但个人缺失时保留团队并将个人置空；截止时间缺失时置空；不从发言人或提议者推断。
- **验收标准**：缺失字段为空或待确认；不会自动生成责任人、日期或证据；`owner_confirmation_status`不因整体确认自动变成已接受。
- **依赖**：ActionItem对象、字段状态、证据索引。
- **证据状态**：产品规则已确认；语义质量待验证。
- **是否MVP必须项**：是。

### MVP-FR-014｜待确认、冲突和弃权

- **用户价值**：宁可显式缺失，也不把不确定内容写成事实。
- **功能描述**：支持`supported`、`evidence_missing`、`conflict`、`low_confidence`、`field_missing`和`human_resolved`等产品状态。
- **前置条件**：模型或规则能够返回候选状态；用户可以查看证据。
- **主流程**：检测风险→显示状态和原因→用户修改、保留待确认或删除。
- **异常流程**：风险状态不得静默隐藏或自动升级为正式结果。
- **验收标准**：责任人、截止时间、结论和证据不足时不补造；正式纪要可以包含独立“待确认事项”区域。
- **依赖**：结构化schema、状态机、界面提示。
- **证据状态**：产品规则已确认；触发阈值待Gold和算法验证。
- **是否MVP必须项**：是。

### MVP-FR-015｜决策与待办人工新增、编辑和删除

- **用户价值**：允许用户纠正漏提取和误提取，完成演示闭环。
- **功能描述**：用户可新增、编辑、删除Decision和ActionItem；人工操作必须记录。
- **前置条件**：进入AI草稿或待确认状态。
- **主流程**：选择对象→编辑字段或新增→保存→显示人工修改标记。
- **异常流程**：无证据的人工新增不得伪造EvidenceLink；删除误提取时保留最小审计。
- **验收标准**：新增、编辑、删除均可回显；人工内容与模型原始输出可区分。
- **依赖**：编辑组件、版本差异、AuditEvent。
- **证据状态**：产品决策已确认；版本一致性待验证。
- **是否MVP必须项**：是。

### MVP-FR-016｜分层证据关联

- **用户价值**：让关键内容可以被核对，同时控制句子级对齐复杂度。
- **功能描述**：决策和待办逐条关联证据；章节和发言人纪要关联代表性时间范围；全文纪要关联章节。
- **前置条件**：TranscriptSegment、Speaker和时间线可用。
- **主流程**：点击条目→显示原话、发言人、时间范围和回放入口。
- **异常流程**：证据缺失或冲突时显示状态，不生成看似完整的引用。
- **验收标准**：决策和待办至少有一个或多个证据片段，或明确标记无证据／待核验；音频删除后入口降级。
- **依赖**：EvidenceLink、播放器、版本记录。
- **证据状态**：产品决策已确认；关联正确率待验证。
- **是否MVP必须项**：是。

### MVP-FR-017｜AI草稿与正式纪要确认

- **用户价值**：防止未经人工核对的AI结果被当作正式记录。
- **功能描述**：仅演示操作人可以在整体检查后确认生成FormalMinutes。
- **前置条件**：全部必要结果生成；处理状态为草稿可确认。
- **主流程**：查看草稿→核对高风险项和证据→修改→点击确认生成正式版本。
- **异常流程**：存在未完成处理、任务失败或用户放弃时不生成正式纪要。
- **验收标准**：确认前文件状态为AI草稿；确认后生成正式版本和确认记录；整体确认不代表个人责任人接受。
- **依赖**：内容状态机、单一演示操作人、版本模型。
- **证据状态**：产品决策已确认；端到端流程待验证。
- **是否MVP必须项**：是。

### MVP-FR-018｜版本、修改和最小审计

- **用户价值**：能够说明正式纪要如何由AI草稿形成，并避免无痕覆盖。
- **功能描述**：保存草稿、正式版本、版本号、确认人显示名、确认时间、父版本和修改记录。
- **前置条件**：存在草稿或正式版本。
- **主流程**：草稿修改→确认→生成正式版本；后续修改生成修订草稿和新版本。
- **异常流程**：写入中断时不产生半成品正式版本。
- **验收标准**：原始AI输出、人工修改和正式版本可区分；关键操作形成AuditEvent。
- **依赖**：版本存储、原子写入、审计记录。
- **证据状态**：产品决策已确认；可靠写入和恢复待验证。
- **是否MVP必须项**：是。

### MVP-FR-019｜HTML、TXT和JSON正式文件

- **用户价值**：让演示结果可以被交付、阅读和后续接入。
- **功能描述**：正式确认后默认生成`formal_minutes.html`、`formal_minutes.txt`和`manifest.json`。
- **前置条件**：FormalMinutes已生成；文件写入位置可用。
- **主流程**：确认→生成三种文件→显示保存位置和版本信息。
- **异常流程**：某文件写入失败时显示失败，不损坏正式纪要对象；允许安全重试。
- **验收标准**：三种文件来自同一正式版本；HTML可交互查看；TXT可独立阅读；JSON包含最小元数据和对象状态。
- **依赖**：文件生成器、schema、PC本地存储。
- **证据状态**：输出范围已确认；具体schema待技术设计。
- **是否MVP必须项**：是。

### MVP-FR-020｜本地加密存储

- **用户价值**：降低演示过程中本地文件被直接读取的风险。
- **功能描述**：PC原始音频、开发板临时副本、转写、草稿、正式纪要和审计记录采用真实本地加密存储。
- **前置条件**：本地加密工作区和单设备／单会话密钥可用。
- **主流程**：写入前加密；读取时在授权的演示进程内解密；文件状态显示加密。
- **异常流程**：密钥或解密失败时拒绝读取并记录错误；不得回退到明文写入。
- **验收标准**：静态文件不是可直接阅读的明文；加密失败不会悄悄保存明文。
- **依赖**：操作系统能力、加密库、密钥边界。
- **证据状态**：真实加密目标已确认；算法、密钥管理和生产级保护待评审。
- **是否MVP必须项**：是。

### MVP-FR-021｜原始音频独立删除

- **用户价值**：允许删除音频而不必删除已确认正式纪要。
- **功能描述**：删除PC原始音频和开发板临时副本；正式纪要保留；证据回放状态降级。
- **前置条件**：存在音频或临时副本；用户执行删除操作。
- **主流程**：选择删除范围→提示影响→确认→清理两端副本→验证结果。
- **异常流程**：任一副本删除失败时显示失败对象和待处理状态。
- **验收标准**：删除成功后不能继续播放源音频；正式纪要和文本可按策略保留；不宣称生产级安全擦除。
- **依赖**：DataObject、删除扫描、证据降级、AuditEvent。
- **证据状态**：产品决策已确认；副本覆盖和擦除等级待验证。
- **是否MVP必须项**：是。

### MVP-FR-022｜放弃确认和草稿保留

- **用户价值**：区分“暂不正式化”和“删除数据”。
- **功能描述**：用户放弃确认后将草稿标记为`abandoned`，不自动删除音频或草稿。
- **前置条件**：草稿已生成但未正式确认。
- **主流程**：点击放弃→确认提示→记录状态和操作时间→可重新进入或单独删除。
- **异常流程**：放弃后不得生成正式文件或外部任务。
- **验收标准**：状态可见；重新进入后仍能查看草稿和证据；删除必须另行操作。
- **依赖**：ConfirmationWorkflow、版本和审计。
- **证据状态**：产品决策已确认；恢复流程待验证。
- **是否MVP必须项**：是。

### MVP-FR-023｜失败、重试和删除审计

- **用户价值**：让用户知道系统是否真的完成了处理或删除。
- **功能描述**：对处理失败、取消、删除请求、删除成功、部分成功和失败形成最小审计记录。
- **前置条件**：发生对应操作或异常。
- **主流程**：记录对象、操作人显示名、时间、阶段、结果和错误原因。
- **异常流程**：审计写入失败时显示系统错误，不宣称操作已完成。
- **验收标准**：失败和成功可区分；审计记录不包含原始音频正文；正式纪要不因删除音频被无痕修改。
- **依赖**：AuditEvent、时间、设备标识。
- **证据状态**：产品决策已确认；日志完整性待验证。
- **是否MVP必须项**：是。

## 9. 数据模型

> 以下是MVP产品语义模型，不冻结数据库表、API路径、消息协议或最终JSON字段命名。实现可根据开发板和PC端架构调整，但不得改变核心语义。

### 9.1 MVP对象

| 对象 | MVP用途 | 关键字段或规则 |
|---|---|---|
| `Meeting` | 单次演示会议 | `meeting_id`、标题、输入文件、创建时间、处理状态、内容状态、版本 |
| `RecordingState` | 文件输入和处理状态，不代表真实录音 | `file_selected`、`uploading`、`processing`、`partial_ready`、`completed`、`failed`、`cancelled` |
| `TranscriptSegment` | 只读逐字片段 | `segment_id`、原始文本、开始／结束时间、`speaker_id`、待核验状态、音频位置 |
| `Speaker` | 匿名说话人 | `speaker_id`、显示标签、合并关系、`unknown`状态；不得自动实名化 |
| `ChapterSummary` | 大模型自主分章和章节纪要 | `chapter_id`、标题、起止时间、摘要、章节证据、顺序、人工调整记录 |
| `FullMinutes` | 根据章节纪要生成的全文会议总结 | `summary_id`、章节引用、全文摘要、待确认内容、生成版本 |
| `SpeakerMinutes` | 按匿名发言人汇总全场重点 | `speaker_id`、重点、章节引用、证据时间范围、生成版本 |
| `Decision` | 已形成或待确认的决策候选 | `decision_id`、内容、状态、证据、核对状态、人工修改记录 |
| `ActionItem` | 决策之外的待办候选 | 见9.2；缺失字段保持为空 |
| `EvidenceLink` | 纪要到原话／时间线的关联 | 片段、说话人、时间、原文、音频可用状态、证据状态 |
| `DraftMinutes` | AI生成且可修改的草稿 | 五类输出、版本、草稿状态、人工修改差异 |
| `FormalMinutes` | 用户确认后的正式版本 | 版本号、确认人显示名、确认时间、父版本、文件状态 |
| `DataObject` | 分对象存储和删除 | 对象类型、存储位置、加密状态、删除状态、证据影响 |
| `AuditEvent` | 最小操作和异常记录 | 操作人、时间、对象、动作、结果、错误原因、设备 |

### 9.2 ActionItem最小字段

```text
action_id
content
responsible_team
individual_owner
ownership_status
deadline
evidence_links[]
confirmation_status
extraction_status
review_status
manual_edit_status
```

### 9.3 ActionItem规则

1. 提议者不自动成为责任人；
2. 团队成员不自动成为个人责任人；
3. 责任团队明确但个人缺失时，`responsible_team`保留，`individual_owner`为空；
4. 截止时间缺失时保持为空；
5. 相对时间和模糊时间不自动转成具体日期；
6. 证据不足时标记待确认；
7. 本MVP不实现个人责任人接受任务；
8. 整体确认不自动把个人责任状态改为已接受；
9. `execution_status`不进入MVP，跨会议执行跟踪明确延期；
10. 人工新增或修改不得伪造语音证据。

### 9.4 文件输出最小元数据

`manifest.json`至少记录：

```text
meeting_id
meeting_title
input_file_name（可按安全策略脱敏）
created_at
processing_status
content_status
minutes_version_id
version_no
confirmed_by_display_name
confirmed_at
included_objects
source_audio_status
evidence_availability
local_only_status
exported_at
related_audit_event_ids
```

## 10. 状态与确认规则

### 10.1 处理状态

```text
未选择
  → 已选择
    → 发送中
      → NPU处理中
        → 部分结果可查看
          → AI草稿完成
            → 可确认
```

### 10.2 内容状态

```text
AI草稿
  → 待确认
    → 正式纪要
      → 修订草稿
        → 待确认
          → 新正式版本
```

### 10.3 音频和对象删除状态

```text
活动中
  → 待删除
    → 已删除
      → 删除已验证

删除失败／需处理
```

音频、开发板临时副本、转写、草稿、正式纪要、证据索引和审计记录分别维护状态。不得用一个“会议已删除”状态掩盖实际处理范围。

### 10.4 正式确认规则

正式确认前必须满足：

- 所有必要处理阶段已完成；
- 全文、章节、发言人、决策和待办结果可查看；
- 决策和待办已经核对或明确保留为待确认；
- 缺失责任人和截止时间保持为空；
- 冲突、低置信和无证据内容没有被静默确定化；
- 用户明确点击确认；
- 系统记录确认人显示名、确认时间、版本号和审计事件。

正式确认不要求：

- 每个责任人单独接受；
- 多人协同签署；
- 生产级可信身份；
- G2/G3指标达到阈值。

## 11. 证据与防编造规则

### 11.1 证据关联层级

| 内容 | 最低证据要求 |
|---|---|
| 决策 | 一个或多个原话片段、匿名发言人、起止时间；无证据则待确认 |
| 待办 | 一个或多个原话片段、匿名发言人、起止时间；责任和时间字段分别核对 |
| 章节纪要 | 一个或多个代表性时间范围，可跳转回放 |
| 发言人纪要 | 关联该匿名发言人的相关片段和时间范围 |
| 全文纪要 | 关联对应章节，不要求每一句总结单独绑定原话 |
| 人工新增内容 | 标记人工补充；没有原话时不得创建伪造EvidenceLink |

### 11.2 防编造规则

- 不从发言人推断姓名、部门或职位；
- 不从提议者推断责任人；
- 不从责任团队推断个人；
- 不从相邻条目复制截止时间；
- 不把“有人建议”写成最终决策；
- 不把“部门被提到”写成部门已经接受任务；
- 不把“一个月”“下个月”“定期”等表达自动改成具体日期；
- 不把模型最高概率值直接当作确定事实；
- 不把章节自动分组当作已经经过人工确认的事实；
- 不把结构化schema合法当作语义正确；
- 不用飞书模型输出替代官方TextGrid和RTTM证据。

### 11.3 待确认展示

待确认内容必须显示：

- 触发原因：无证据、冲突、低置信或字段缺失；
- 当前缺失字段；
- 相关证据入口；
- 是否可以人工修改；
- 是否会阻止某条内容进入已确认决策或待办。

待确认内容可以随正式纪要保留，但不得计入“已确认决策”或“已确认待办”。

## 12. 安全、存储和删除

### 12.1 数据路径

```text
PC本地原始WAV
  → PC加密工作区
  → 局域网发送临时副本
  → 开发板加密临时工作区
  → NPU处理
  → 结果通过局域网返回PC
  → PC加密工作区保存草稿和正式纪要
```

运行期间：

- 不调用公共云；
- 不向外部服务上传音频、转写、纪要或证据；
- PC与开发板之间的传输状态可见；
- 运行时网络拓扑、详细协议和抓包不在MVP界面展示。

### 12.2 加密边界

- 加密算法；
- 密钥存放位置；
- 密钥轮换；
- 企业密钥托管；
- 设备丢失和维修场景的生产级保护；
- 安全认证或合规等级。

如果加密实现失败，不得静默退回明文写入。演示阶段使用的加密方案必须在技术验证记录中明确标注为MVP实现，不得称为量产方案。

### 12.3 音频删除

删除操作应：

1. 显示将删除PC源文件和开发板临时副本；
2. 显示正式纪要将继续保留；

## 14. 验证计划

### 14.1 验证顺序

```text
PC—开发板局域网连通
  → WAV输入校验
  → 小样本NPU处理
  → 结果回传和状态机
  → 回放、逐字稿、发言人和证据跳转
  → 章节和全文生成
  → 决策与待办编辑
  → 正式文件生成
  → 加密和删除流程
  → 再验证120分钟输入
```

### 14.2 演示样本

- 使用单独准备的非敏感WAV；
- 样本应覆盖至少一个章节、多个匿名发言人、一个决策和一个待办；
- 样本应包含至少一个缺失字段或待确认案例，以验证不补造规则；
- 演示结果只用于内部技术展示和流程检查。

### 14.3 官方样本验证

| 样本 | 用途 | 当前状态 |
|---|---|---|
| 录音1 | 长会议、连续转写和说话人基础检查 | 官方ASR／说话人Gold可用；实验未执行 |
| 录音2 | 官方Gold和结构化候选桥接检查 | 官方ASR／说话人Gold可用；23条语义候选不作为最终Gold |
| MA-ACTION-001 | 受控边界回归样本 | 真人音频尚未形成；不作为当前MVP输入要求 |

### 14.4 端侧验证

至少验证：

- 断开公网时PC—开发板闭环；
- 120分钟输入的处理完整性、资源和时延；
- 局域网中断、NPU失败、取消和重试；
- PC源文件和开发板临时副本的清理；
- 处理期间只允许一个任务；
- 分阶段结果不会被误认为正式纪要；
- 文件生成失败不会损坏正式版本。

### 14.5 安全与生命周期验证

至少验证：

- 规定对象是否确实加密存储；
- 加密失败是否阻止明文回退；
- 删除范围是否覆盖PC源文件和开发板临时副本；
- 删除正式纪要时是否不会被音频删除动作误删；
- 删除成功和失败是否被正确记录；
- 音频删除后回放入口是否失效；
- 审计记录是否不包含不必要的会议正文。

## 15. 延期项、风险与后续路线

### 15.1 主要风险

| 风险 | 影响 | 当前应对 |
|---|---|---|
| 120分钟NPU资源不足 | 处理超时、内存不足或结果不完整 | 先小样本验证，再进行长音频压测；不提前承诺性能 |
| WAV声道或输入接口未冻结 | 传输成功但NPU无法正确处理 | 将采样率、位深、声道和输入适配列为技术待定项 |
| 自动分章质量不足 | 章节和全文摘要不稳定 | 支持章节合并、拆分、重命名和重新生成 |
| 说话人错误 | 发言人纪要和证据归属错误 | 匿名标签、`unknown`和最小人工修正 |
| 结构化模型补造字段 | 错误责任和日期进入正式纪要 | 空值、待确认、证据门和人工确认 |
| 长任务等待体验差 | 用户误以为系统卡死 | 阶段状态、取消、失败原因和重试 |
| 局域网不稳定 | 任务失败或重复处理 | 明确失败，从头重试，不做隐式恢复 |
| 加密实现不完整 | 演示结论被误解为安全能力 | 记录实现边界，不宣称生产级密钥管理 |
| 文件删除覆盖不全 | 无法证明数据已清理 | 分对象状态、删除验证和失败可见 |
| 竞品参考过度复制 | 范围膨胀或产生知识产权风险 | 只参考信息结构和交互启发，不复制资产或能力结论 |
| 单样本误外推 | 形成错误质量结论 | 演示样本与验证样本分开，结果描述性报告 |

### 15.2 后续版本前移条件

只有出现以下证据，才考虑把延期能力前移：

- 真实用户明确要求现场录音和物理静音；
- 120分钟验证表明单任务链路稳定，且用户需要更长会议；
- 真实用户明确要求多人权限或个人责任人接受；
- 客户明确要求PDF、USB或局域网分发；
- Gold和错误分析证明遗留事项、开放问题或被否决方案必须独立建模；
- 真实用户需要跨会议任务跟踪；
- 安全、法务和客户制度完成相应评审。

### 15.3 不因演示效果前移的能力

不得仅因演示吸引力把以下能力前移到当前MVP：

- 实时字幕；
- 多语言翻译；
- 公共云协作链接；
- 自动PPT；
- 情绪分析；
- 数字人；
- 外部任务自动同步；
- 未经确认的自动发布。
