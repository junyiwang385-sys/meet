## 1. 产品摘要

### 1.1 候选产品定义

> **面向内容敏感、经授权可以录音的企业固定会议室，在设备端或客户控制环境内完成会议采集、理解、核验和治理，并通过会尾共享大屏共同确认决策与行动项，最终形成可追溯、可修订、可删除和可受控流转的正式纪要。**【产品暂定决策】【需求假设，待真实用户验证】

### 1.2 暂定产品形态

```text
设备端会议 Agent
  ＋ 共享显示／投影画面
  ＋ 可选麦克风阵列
  ＋ 本地存储与受控导出
```

本版只定义逻辑产品形态，不绑定最终投影机、一体机、外接盒子、芯片、屏幕尺寸或麦克风SKU。【产品暂定决策】

### 1.3 P0候选核心闭环

```text
明确授权
  → 本地录音与持续状态提示
  → 离线普通话转写与说话人分段
  → 提取决策、行动项、依赖和未解决问题
  → 标记缺失、纠正、否定和不确定内容
  → 关键条目关联原话证据
  → 会尾共享大屏共同核对
  → 主持人或授权确认人确认
  → 生成正式纪要版本
  → 本地保存、原始音频独立删除或受控USB导出
```

### 1.4 产品差异化

本产品不以“另一个转写和摘要工具”为目标，候选差异化由以下五部分共同构成：

1. **本地安全处理**：核心会议内容默认不发送外部公共云；
2. **会尾共同确认**：参会者离开会议室前共同核对关键结果；
3. **行动项闭环**：分离任务、责任团队、个人责任人、截止时间、验收标准和依赖；
4. **证据可追溯**：关键结论可回到原话、说话人和时间位置；
5. **正式纪要治理**：AI草稿只有经授权确认后才成为正式版本，并保留修订、分发、删除和审计状态。

### 1.5 P0候选成功定义

P0是否成立，不以“能够生成一篇摘要”判断，而以三个候选质量门共同判断：

| 质量门 | 目标 | 当前状态 |
|---|---|---|
| G1 安全与授权 | 用户知道何时录音、数据在哪里处理，并能控制停止、删除和导出 | 待真实用户、设备与安全验证 |
| G2 内容可信 | 关键结果可核对，缺失字段不补造，纠正和否定关系正确 | 待真人录音Gold验证 |
| G3 正式闭环 | AI草稿可通过会尾确认转化为受治理的正式纪要 | 待原型、权限和真实会议验证 |

三个质量门均达到后，才可以声明产品完成首版闭环。【产品分析】

## 2. 背景与问题定义

### 2.1 候选业务问题

| 问题 | 当前常见处理方式 | 候选产品机会 | 验证状态 |
|---|---|---|---|
| 会后人工整理耗时，决策和任务容易遗漏 | 主持人、秘书或项目经理手写纪要 | 自动形成结构化草稿并在会尾完成核对 | 【需求假设，待真实用户验证】 |
| 部分敏感会议不愿上传外部公共云 | 放弃会议AI，或组合本地录音和人工文档 | 在客户控制环境内完成核心闭环 | 【需求假设，待真实用户验证】 |
| 完整逐字稿不能直接推动执行 | 会后人工再次提炼任务 | 直接形成决策、行动项、依赖和未决问题候选 | 【产品分析】 |
| AI可能把建议写成决定，或补造责任人和日期 | 反复回听和人工改写 | 缺失字段显式保留，关键字段有证据 | 【脚本级Gold规则】 |
| 会后异步确认产生多版本和责任争议 | 群聊、邮件或下次会议再确认 | 用共享大屏在会尾共同确认 | 【需求假设，待真实用户验证】 |
| 关键结论无法快速回到原话 | 搜索全文或拖动时间轴 | 条目级证据直接定位原话和音频 | 【产品分析】【质量目标，待Gold验证】 |
| 音频、转写和纪要需要不同保留策略 | 在多个工具中分别管理 | 在同一治理模型中分对象保存和删除 | 【安全或生命周期要求，待评审】 |

### 2.2 核心产品问题

本产品需要验证的核心问题不是“模型能否生成摘要”，而是：

> 在敏感、允许授权录音的企业会议中，能否以用户可理解和可控制的本地方式，把会议内容转化为可信的结构化结果，并在现场形成可执行、可追溯和可治理的正式纪要？

### 2.3 价值成立的必要条件

1. **需求成立**：目标企业确实存在高频“允许录音但不愿使用外部公共云”的会议；
2. **能力成立**：端侧转写、说话人、结构化提取、证据和状态管理达到可用门槛；
3. **交互成立**：参会者愿意使用会尾大屏完成核对，且耗时可接受；
4. **安全成立**：数据路径、删除、导出和权限可以被客户验证；
5. **产品载体成立**：投影或共享大屏相比电脑、手机和独立录音设备提供明显现场价值。

以上均未完成全面验证。

## 4. 产品目标与非目标

### 4.1 P0候选产品目标

1. 在无外部公共云依赖的条件下完成一次会议核心闭环；
2. 在录音前获得明确授权，并持续显示录音、静音、联网和处理状态；
3. 生成可纠错的普通话转写和基础说话人分段；
4. 结构化提取决策、行动项、责任归属、截止时间、依赖和未解决问题；
5. 对缺失、模糊、否定和纠正内容显式处理，不自动补造；
6. 为关键结论建立条目级原话证据；
7. 通过会尾投影页面完成共同核对；
8. 只有主持人或被明确授权的确认人才能生成正式纪要；
9. 支持正式版本、修订版本、分发状态和删除状态治理；
10. 暂定通过受控USB导出正式纪要，并保证失败不损坏本地正式版本。

以上是PRD v0.1的候选工作范围，不代表最终P0已冻结。

### 4.2 P0明确非目标

- 多语言转写、翻译和实时字幕；
- 云端备用转写作为默认链路；
- 未经人工确认自动发布正式纪要；
- 未经确认自动创建外部任务；
- 自动补全缺失责任人、团队、截止时间或依赖日期；
- 跨会议行动项持续跟踪；
- 公共云链接作为默认分享方式；
- 默认使用声纹或人脸进行实名识别；
- 通用聊天机器人、情绪分析、数字人和自动PPT；
- 超大会议、复杂远场和完美重叠发言分离承诺；
- 最终硬件SKU、BOM、价格和量产规格；
- 最高涉密等级或特定法规认证承诺。

## 5. PRD v0.1暂定产品决策

以下决策仅用于组织本版PRD，不代表真实用户、技术、安全或采购验证已完成。

| ID | 暂定方向 | 对PRD的约束 |
|---|---|---|
| PD-01 | 设备端会议Agent＋共享显示＋可选麦克风阵列 | 不绑定最终硬件SKU |
| PD-03 | 默认不使用外部公共云；客户局域网需单独授权和说明 | 本地与客户控制环境必须可解释 |
| PD-04 | 核心对象是经确认的决策、行动项和正式纪要 | 逐字稿主要作为证据和纠错基础 |
| PD-05 | 主持人或被明确授权的确认人生成正式纪要 | 普通编辑行为不等于正式确认 |
| PD-06 | 缺失字段进入待确认或遗留问题 | 不阻止其他完整且已核验内容正式确认 |
| PD-07 | P0只处理单次会议提取和确认 | 跨会议持续跟踪放入P1 |
| PD-10 | 受控USB暂定为P0主导出路径 | 局域网分发作为P1候选 |
| PD-11 | 最小角色包括设备管理员、主持人/确认人、普通参会者、安全审计员 | 更细角色和策略后续扩展 |
| PD-14 | P0不连接外部任务系统 | P1仅同步人工确认后的行动项 |
| PD-15 | AI草稿→待确认→正式纪要→修订草稿→已修订 | 分发状态独立，删除按对象记录 |

### 5.1 仍未决定的关键事项

| 事项 | 本版处理 | 冻结前所需证据 |
|---|---|---|
| 最终目标会议人数和时长 | 暂按3～15人、30～120分钟描述 | 真实用户访谈和设备测试 |

| 准确率和性能门槛 | 保留候选目标/TBD | 音频级Gold和端侧压测 |

## 8. 端到端用户流程

### 8.1 主流程

| 阶段 | 用户动作 | 系统候选行为 | 完成条件 |
|---|---|---|---|
| 会前配置 | 选择会议、主持人、参会人、保密等级和数据策略 | 显示处理位置、联网状态、存储、麦克风和授权信息 | 授权完成，设备可开始录音 |
| 会中记录 | 开始、暂停、静音、继续或停止录音 | 本地录音、转写、说话人分段、结构化草稿和证据缓存；状态持续可见 | 主持人停止录音 |
| 会尾准备 | 等待或进入草稿确认 | 聚合决策、行动项、依赖、未决问题和缺失字段 | 草稿达到可展示状态 |
| 会尾核对 | 查看、编辑、删除、合并、补字段、转遗留问题和查看证据 | 保留人工修改差异，不用模型自动补造字段 | 授权确认人决定确认或稍后处理 |
| 正式生成 | 确认内容、分发范围和音频处理选择 | 生成正式版本、确认记录、审计事件和数据对象状态 | 正式版本完整写入 |
| 会后管理 | 查看、修订、导出或删除 | 保留版本链，执行权限和生命周期策略 | 按企业策略持续管理 |

### 8.2 录音状态模型

```text
未授权
  → 已授权／待录音
    → 录音中
      ↔ 已静音／已暂停
      → 已停止
        → 本地处理中
          → 草稿可确认
```

保护条件：

- 未授权不得进入录音中；
- 物理静音时不得继续采集有效麦克风音频；
- 录音、静音、暂停、停止和处理状态必须持续可见；
- 断开公网不应导致核心流程退出，但实际能力需设备验证；
- 麦克风异常或存储不足不得伪装成正常录音。

### 8.3 内容状态模型

```text
AI草稿
  → 待确认
    → 正式纪要
      → 修订草稿
        → 待确认
          → 已修订（新正式版本）
```

内容状态可按权限和策略进入“已删除”。分发状态与内容状态独立管理。

### 8.4 分发状态模型

```text
未分发 → 分发中 → 已分发
              ↘ 分发失败
已分发 → 已撤回（如后续能力支持）
```

P0暂定支持受控USB导出，不承诺可撤回已经复制到外部介质的文件；该边界必须在导出前明确提示。【安全或生命周期要求，待评审】

### 8.5 数据对象删除状态

```text
活动中 → 待删除 → 已删除 → 删除已验证
                    ↘ 删除失败／需处理
```

音频、转写、AI草稿、正式纪要、证据索引和审计记录分别维护状态，不得用一个“会议已删除”状态掩盖实际删除范围。

### 10.3 责任归属模型

候选字段：

- `responsible_team`：明确承担责任的组织、部门、项目组或职能团队；
- `individual_owner`：经明确指派、自我承诺或人工确认的具体人员；
- `ownership_status`：责任归属完整程度；
- `ownership_evidence`：支持团队或个人归属的原话或人工确认记录；
- `owner_confirmation_status`：具体责任人是否确认接受任务。

`owner_confirmation_status`候选值：

| 候选值 | 适用条件 | 处理要求 |
|---|---|---|
| `not_required` | 当前没有个人责任人 | 不要求个人确认；责任归属仍按`ownership_status`显示为待指定或团队已明确、个人待指定 |
| `pending` | 已指定个人责任人，但尚未确认接受 | 保持待确认，不得展示为责任人已接受 |
| `confirmed` | 个人责任人已明确接受 | 记录确认人、确认时间和确认来源 |
| `rejected` | 被指定人员明确拒绝 | 条目返回责任归属待处理状态，不得自动推断或替换其他责任人 |

候选责任归属状态：

| 责任团队 | 个人责任人 | `ownership_status` | 展示方式 |
|---|---|---|---|
| 缺失 | 缺失 | `unassigned` | 责任团队待指定；个人责任人待指定 |
| 已明确 | 缺失 | `team_assigned_person_pending` | 已明确责任团队；个人责任人待指定 |
| 缺失 | 已明确 | `person_assigned` | 显示具体责任人；团队可待补充 |
| 已明确 | 已明确 | `person_assigned`或`confirmed` | 同时显示团队和个人 |

防错误推断要求：

1. 已明确团队但没有具体人员时，不得标记为完全无责任归属；
2. 不得因为某人属于责任团队就自动指定该人员；
3. 不得因为某人提出任务就自动指定该人员；
4. 不得从相邻任务借用团队、责任人或日期；
5. 团队责任和个人责任分别关联证据；
6. “团队已明确、个人待指定”可进入遗留问题，但不得展示为个人责任完整的已确认任务。

### 10.4 截止时间模型

候选字段语义：

- 原始时间表达必须保留；
- 规范化时间仅在语义明确或有企业规则时填写；
- 缺失时间显示“待确定”；
- 模糊时间显示原文并标记“具体时刻未明确”；
- 时间纠正仅将最终值作为当前有效值，旧值进入证据和修订记录；
- 相邻任务的日期不得跨条目复制。

### 10.5 正式纪要版本模型

正式版本至少记录：

- 版本ID和版本号；
- 当前内容状态；
- 父版本；
- 确认人和确认时间；
- 关键条目及证据；
- 保密等级和分发范围；
- 音频处理选择；
- 人工修改差异；
- 导出和删除状态；
- 关联审计事件。

## 11. 语义提取与证据规则

### 11.1 决策规则

- 只有明确达成并具有约束含义的结论进入决策候选；
- 建议、偏好、普通讨论、技术权衡和被否定方案不生成正式决策；
- 同一决策的补充确认不重复生成新决策；
- 会议语义上明确的决策仍先进入AI草稿，产品内确认后才成为正式纪要。

### 11.2 行动项规则

- 至少存在明确动作，才可进入行动项候选；
- 责任团队、个人责任人或截止时间允许缺失，但必须醒目标记；
- 发言人不等于任务责任人；
- 提出者不等于任务责任人；
- 同一任务在多个说话人、多个片段间补充时，不应被拆成多个任务；
- 验收标准、依赖和执行状态没有明确证据时保持缺失。

### 11.3 依赖与未解决问题规则

- 依赖项与行动项独立建模并建立关联；
- 依赖未到位不等于任务取消；
- 未解决问题保持未决状态；
- “需要与某部门确认”不自动产生具体责任人或期限；
- 争议内容不由AI裁决，可关联多个证据片段。

### 11.4 证据关联要求

每项正式决策和已确认行动项至少具有：

```text
条目ID与版本
  ＋ 一个或多个证据片段ID
  ＋ 原始发言人或候选说话人
  ＋ 开始和结束时间
  ＋ 原始转写
  ＋ 音频定位（音频存在时）
  ＋ 待核验／已核验状态
  ＋ 人工修改和最终确认记录
```

关键规则：

- 时间纠正需要同时关联旧值、纠正发言和最终确认发言；
- 人工补充的责任人必须标记为人工确认证据，不能伪造成语音证据；
- 没有可靠证据时显示“待核验”，不得生成看似完整的引用；
- 修改结构化内容不能覆盖原始AI输出和原证据关系；
- 只有全文时间轴入口不算条目级证据闭环。

### 11.5 原始数据删除后的证据降级

| 源数据状态 | 条目证据状态 |
|---|---|
| 音频和转写均存在 | 原文＋音频可核验 |
| 音频已删除、转写保留 | 仅转写可核验 |
| 音频和转写均删除 | 原始证据已按策略删除；正式纪要可按策略保留 |

删除后不得继续显示无效播放入口。是否保留哈希、摘要指纹或删除证明不在本版冻结。

## 12. 会尾投影确认体验

### 12.1 进入条件

- 录音已停止，或主持人明确进入会尾确认；
- AI草稿已达到可展示状态；
- 当前内容状态明确显示为“AI草稿”或“待确认”；
- 主持人或授权确认人在场；
- 公共屏展示范围符合会议保密策略。

### 12.2 默认信息优先级

```text
顶部：会议名称｜录音已停止｜本地处理状态｜联网状态｜数据外发状态｜保密等级

决策区：候选决策｜状态｜证据入口
行动项区：任务｜责任团队｜个人责任人｜截止时间｜依赖｜缺失字段
未决区：未解决问题｜风险｜争议｜待补信息

底部：稍后确认｜返回修改｜确认并生成正式纪要
```

完整逐字稿不默认铺满主界面，按权限和需要展开。【产品暂定决策】【需求假设，待真实用户验证】

### 12.3 候选确认步骤

1. 先核对候选决策；
2. 删除或降级普通讨论和错误决策；
3. 核对行动项、责任团队、个人责任人、截止时间、验收标准和依赖；
4. 突出显示缺失字段和模糊时间；
5. 责任人核对自己的任务信息；
6. 点击条目查看相关原话和证据；
7. 纠正内容展示最终有效值，同时可查看旧值；
8. 无法解决的争议转为未解决问题；
9. 选择分发范围和音频处理方式；
10. 由授权确认人生成正式纪要。

### 12.4 正式确认完成条件

- 正式决策具有明确语义和证据；
- 作为“字段完整任务”确认的行动项具有个人责任人和截止时间；
- 缺失字段条目已补充，或明确转入待确认/遗留问题；
- 未解决问题没有被写成已确认决策；
- 没有模型补造的责任人、团队、日期或依赖；
- 确认人、确认时间和版本可完整记录；
- 分发范围和音频处理选择已明确。

### 12.5 体验目标边界

- “会尾1～3分钟完成确认”仅为候选目标，需真实用户测试；
- “一次主要操作进入证据”仅为候选目标，需原型验证；
- 无触控设备可考虑遥控器、键鼠或主持人终端，但本PRD不冻结交互硬件；
- 草稿处理未完成时允许稍后确认，但不得生成正式纪要。

## 13. 本地、安全与数据生命周期要求

### 13.1 客户控制环境候选定义

- 会议音频、转写、说话人结果、结构化结果和证据默认不发送外部公共云；
- 核心闭环在断开公网时仍可运行；
- 客户局域网服务器如被采用，必须明确其属于客户控制环境并单独授权；
- 软件升级、模型升级、许可、遥测和故障日志不得隐含传输会议正文或音频；
- 所有外发路径必须有清单、策略、用户可见状态和审计；
- “设备联网”和“会议数据是否外发”必须分别展示。

以上边界需产品、安全、法务和目标客户共同确认。

### 13.2 候选数据流

```text
麦克风／音频输入
  → 本地临时缓冲
  → 本地ASR
  → 本地说话人分段
  → 本地结构化提取
  → 本地证据索引
  → AI草稿
  → 会尾确认
  → 本地正式纪要
  → 受控USB导出
```

任何实际实现若偏离该路径，必须重新评估产品定位和安全声明。

### 13.3 分对象生命周期

| 数据对象 | P0候选要求 | 未决事项 |
|---|---|---|
| 原始音频 | 本地加密存储；可在确认后独立立即删除或按策略保留 | 加密算法与密钥实现、默认期限、擦除等级、缓存和备份副本 |
| 转写文本 | 本地加密存储；与音频分开治理并支撑证据核验 | 保存期限、脱敏和音频删除后的策略 |
| AI草稿 | 本地加密存储；不作为正式依据，可删除或按策略自动过期 | 默认过期时间和恢复策略 |
| 正式纪要 | 本地加密存储；按权限查看、修订、删除和导出 | 企业期限、法律保留和备份策略 |
| 证据索引 | 本地加密存储；与源数据联动，源数据删除后状态降级 | 是否保留指纹或删除证明 |
| 审计记录 | 本地加密存储并记录关键操作，正文最小化 | 保存期限、访问角色和不可篡改要求 |

### 13.4 加密和密钥要求边界

本版只定义以下安全目标，不选择算法、芯片或密钥实现：

- 静态会议数据必须采用本地加密存储；
- 密钥不得与会议数据以同等风险方式存放；
- 管理、确认、审计和维护权限应分离；
- 设备丢失、磁盘拆卸、维修和恢复出厂场景不得轻易暴露会议内容；
- 厂商维护人员默认不得读取客户会议内容和密钥；
- USB文件是否加密、水印、设有效期或绑定接收者，需后续威胁建模与客户验证。

### 13.5 受控USB导出要求

- 暂定作为P0主导出路径；
- 默认只导出正式纪要，草稿导出需要单独授权；
- 导出前显示文件对象、版本、保密等级、接收范围及是否包含证据；
- 原始音频不得默认随纪要导出；
- 未授权导出必须阻止并记录；
- 导出成功、失败和阻止均应形成审计事件；
- 导出失败不得损坏本地正式版本；
- 对外部USB文件的二次复制、撤回和有效期能力尚未确认。

MA-ACTION-001中的U-001继续保留为未解决问题：是否允许导出原始音频，以及是否必须使用水印和有效期，不在本PRD中做最终决定。【脚本级Gold规则】

## 14. 主要异常流程

| 异常 | P0候选处理 |
|---|---|
| 参会者不同意录音 | 不开始录音，或按企业规则退出录音流程 |
| 授权被撤回 | 立即提供停止或静音能力；后续数据按企业规则处理 |
| 麦克风无信号或被静音 | 持续提示，不得假装正常录音 |
| 断开公网 | 核心流程继续；显示断网和数据路径状态 |
| 存储空间不足 | 会前预警；必要时阻止开始；不得静默丢失音频 |
| 转写或结构化处理积压 | 显示进度；允许稍后确认；不得生成伪完整结果 |
| 说话人不确定 | 使用未知或候选标签，允许会尾修正 |
| 责任团队、个人责任人或截止时间缺失 | 醒目标记，不补造；允许补充或转遗留问题 |
| 时间被后续发言纠正 | 当前值更新为最终有效值；旧值保留在证据和修改记录 |
| 决策存在争议 | 转为未解决问题，并保留相关证据，不由AI裁决 |
| 确认人不在场 | 保持待确认，不发布正式纪要 |
| 确认过程中断电 | 恢复最近安全状态；正式版本不得部分写入 |
| 音频在确认前被要求删除 | 提示证据影响；按权限执行并更新证据状态 |
| 未授权导出 | 阻止并记录安全事件 |
| USB导出失败 | 保留本地正式版本，提示原因并允许安全重试 |
| 删除失败或仍存在副本 | 显示“删除失败／需处理”，不得宣称已彻底删除 |
| 设备时间异常 | 阻止或提示确认时间可靠性问题，避免生成错误审计时间 |

| G2 | 评测ASR和说话人分段 | CER、关键字段错误、DER/JER和错误样例 |
| G3 | 评测决策、任务、字段、依赖、未决问题、防编造和证据 | 语义评测报告 |
| G4 | 增加不同会议、噪声、口音、隐含任务和重叠发言 | 分层Gold集 |
| G5 | 独立标注者复核高风险字段 | 一致性和仲裁规则 |

### 17.3 端侧验证

| 阶段 | 验证内容 |
|---|---|
| D0 | 断网完成录音、转写、结构化草稿、证据、确认、保存和USB导出 |
| D1 | 30、60、120分钟连续处理和资源压测 |
| D2 | 距离、座位、噪声、音量和多人轮流发言场景 |
| D3 | 断电、进程重启、存储不足、麦克风断开和处理中断恢复 |
| D4 | 授权、录音、静音、暂停、停止和状态显示联动 |
| D5 | 公网、局域网、升级、日志和遥测场景的数据路径检查 |

### 17.4 安全与生命周期验证

| 阶段 | 验证内容 |
|---|---|
| L0 | 盘点音频、缓存、转写、草稿、纪要、证据、审计、备份和临时文件 |
| L1 | 威胁建模、静态保护、密钥位置、权限、设备丢失和维修 |
| L2 | 分别删除音频、转写、草稿和正式纪要，并验证证据降级 |
| L3 | 到期删除、策略变化、失败重试和法律保留冲突 |
| L4 | USB权限、加密/水印候选方案、失败、恶意介质和审计 |
| L5 | 备份恢复、恢复出厂、设备回收和不可恢复删除边界 |

### 17.5 会尾体验验证

至少验证：

- 3～15人是否能理解录音和数据状态；
- 默认信息量是否适合共享屏；
- 缺失字段是否足够醒目；
- 查看证据是否快速且不打断会议；
- 主持人和责任人是否能共同完成核对；
- 无触控设备的交互方式；
- 稍后确认是否造成遗忘或多版本；
- 候选1～3分钟目标是否现实。

## 19. 关键风险与缓解方向

| 风险 | 可能影响 | 当前缓解方向 |
|---|---|---|
| 真实需求强度不足 | 产品差异化无法转化为采购价值 | 优先访谈敏感会议高频角色，不以内部推断替代证据 |
| 会尾确认打断会议 | 核心投影差异化不成立 | 原型测试信息量、交互方式和确认时长 |
| 转写或说话人质量不足 | 后续结构化结果和证据不可信 | 建立真人音频Gold，保留未知标签和快速纠错 |
| 结构化模型补造字段 | 错误任务进入正式纪要 | 缺失字段强制空值、证据门和人工确认 |
| 本地算力不足 | 长会议处理积压、等待过长 | 30/60/120分钟压测后再冻结模型和硬件 |
| “本地”数据路径不可证明 | 安全定位失信 | 数据流图、抓包、接口清单和遥测审查 |
| USB成为外泄路径 | 无法通过信息安全评审 | 默认最小导出对象、权限、提示、审计和安全方案验证 |
| 删除无法覆盖缓存和副本 | 错误宣称数据已彻底删除 | 分对象盘点、删除状态和失败可见性 |
| 管理员权限过大 | 会议正文被无关运维人员访问 | 设备管理权与内容访问权分离 |
| 产品形态过早绑定 | 限制部署方式并增加BOM风险 | v0.1只定义逻辑形态，不冻结SKU |
| 范围持续扩大 | P0无法形成闭环 | 坚持单会、普通话、本地、确认和治理主线 |

## 20. 后续版本边界

### 20.1 P1前移条件

仅在验证出现以下证据时考虑把P1能力前移：

- 真人Gold表明企业术语错误直接破坏关键决策和任务，可前移基础词库；
- 首批客户禁止USB且必须内网流转，可前移局域网受控分发；
- 客户明确要求更细角色和独立审计，可前移部分权限能力；
- 单会闭环不能满足真实使用，可重新评估跨会议行动跟踪；
- 真实用户明确要求日程或任务集成，仍只能同步人工确认内容。

### 20.2 不因演示效果前移的能力

以下能力不得仅因演示吸引力进入P0：

- 实时字幕；
- 多语言翻译；
- 自动PPT；
- 历史会议问答；
- 情绪和注意力分析；
- 数字人；
- 公共云协作链接；
- 未经确认的自动任务同步。

## 21. PRD v0.1开放问题

1. 首批ICP和最高优先行业是否成立；
2. 会尾共同确认是否应成为最终P0，以及用户可接受时长；
3. 是否需要每名责任人分别确认自己的行动项；
4. “责任团队已明确、个人待指定”的条目能否进入正式纪要正文，还是只能进入遗留问题；
5. 原始音频的默认保留时间和删除证明等级；
6. 音频删除后是否保留转写、摘要指纹或其他证据；
7. USB导出是否允许包含转写证据或原始音频；
8. USB文件是否必须加密、水印、设有效期或绑定接收者；
9. 谁可以确认、删除、导出和查看审计；
10. 设备管理员是否完全不能读取会议正文，紧急维护如何处理；
11. 无触控投影环境下的会尾交互方式；
12. 企业词库是否需要前移P0；
13. 最终产品是新投影、外接模块还是会议一体终端；
14. 可选麦克风阵列是否被目标客户接受；
15. 端侧模型、硬件、存储和散热能否支撑目标会议；
16. 客户局域网是否进入P0还是维持P1；
17. 准确率、时延、稳定性和安全指标的最终定义；
18. 采购主体、预算、试点条件、售后和认证要求。

## 22. 本版结论

### 22.1 当前可执行结论

- 已形成统一的候选产品定义、核心闭环和非目标；
- 已将10项起草前暂定产品决策落实到PRD结构；
- 已定义P0候选功能、角色、流程、状态、数据、证据、异常和验证要求；
- 已将责任团队与个人责任人分离建模；
- 已用MA-ACTION-001建立脚本级语义追踪；
- 已明确真实用户、Gold、端侧、安全和生命周期的验证门。

### 22.2 当前不可执行结论

本PRD不能用于宣称：

- 真实用户已经确认需求；
- P0最终范围已经冻结；
- 产品已达到任何准确率、性能或安全指标；
- 某一模型、芯片、投影设备或麦克风已经确定；
- 受控USB的安全实现已经完成；
- 数据生命周期已经符合特定客户或法规要求；
- BOM、价格、发布日期和研发资源已经承诺。

### 22.3 后续工作原则

后续工作应围绕以下证据链推进，而不是继续无边界增加功能：

```text
真实用户确认问题成立
  → 真人音频Gold确认内容可信
  → 端侧设备确认能力可行
  → 会尾原型确认交互成立
  → 安全与生命周期确认可治理
  → 再冻结P0、指标、方案和研发承诺
```
