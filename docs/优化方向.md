# 优化方向（后续 roadmap）

> 给接手人的「如果继续做，往哪走」。每个方向都扣住**已测出的结论**（见 `docs/实验与各阶段成果.md`、`docs/OPEN-ITEMS.md`、`CLAUDE.md`），不凭空提。均为**未来方向**，非已完成。

四个方向及依赖关系：

```text
方向4 前端会议资料写入(入口) ──喂词表/域信息──▶ 方向2 领域知识库/RAG 专名纠错 ──▶ 提专名召回(热词已验 B-WER 减半)
方向3 专用理解性模型分章  ── 独立，攻分章天花板
方向1 模型微调(需更大显存)── 独立，先验 ROI(之前是负结果)
```

**建议优先级**：方向 4+2（专名闭环，增益已验证、性价比高）＞ 方向 3（分章）＞ 方向 1（微调，先小规模验 ROI）。

---

## 方向 1 · 模型微调（针对测试总结的弱项 + 更大显存）

**动机（已测）**：4B 强检索/受控抽取，弱**自主归纳（≤30%）/低频信息（数字·专名易漏）/篇章**（`CLAUDE.md`）。TextGrid 对照实证：发言人 4/6、待办 0/1（幻觉）、财务数字漏。之前 QLoRA 尝试是**负结果**（召回 0.167→0.024），根因是 **8G 显存**（训练数据被迫滤到 17 对 + 推理截断 3072 → 过拟合 + 评测被污染），**不是方法错**。

**目标（只打测出来的弱项）**：提升**块级受控抽取/摘要**质量（域适配）——低频事实召回（数字/专名不漏）、发言人归属、块摘要完整性（不丢负责人）。**不是**教它自主全局归纳（架构已用确定性脚手架绕开）；死守**不编造**（over_decision=0 是我方唯一强项，不能被微调带坏）。

**方案**：沿用已跑通的 QLoRA 栈（peft/trl/bitsandbytes，见 `eval/finetune/`），在 **≥12–24G 卡**上重做——
- 完整长块（不再砍到 4096）、更多蒸馏数据（train_S 53 场，教师 opus/fable 生成块摘要，不升格 / anchors 原样 / owner 逻辑）；
- 少 epoch 防过拟合；**train/test 分离**（train_S 训 / golden-30 测，严禁泄漏）；
- held-out 上评：核心事实召回↑ 且 over_decision/忠实度不劣化（golden_v2 scorer）；
- 过关 → 合并 LoRA → 重量化 RKLLM W4A16 → 板端重验。

**依赖/成本**：**≥12–24G GPU（硬约束，现两块可用卡都是 8G）**；板端 int4 重量化可能吃掉部分收益（须板端复验）。

**诚实边界**：之前负结果；架构已绕开归纳 → 微调收益可能有限。**建议先小规模验 ROI 再投**（别默认它一定有用）。参见 `docs/OPEN-ITEMS.md`「已弃」条与 `eval/finetune/`。

## 方向 2 · 领域知识库 / RAG（做专有名词纠错）

**动机（已测）**：核心事实召回的残余漏项大头是**专名类事实**（招生办→「赵正半」、财务数字听错）；ASR 28% CER 里专名占一块。当前专名纠错 `stages/postprocess.py::correct_proper_nouns` 已实现（拼音音节规则圈候选 + 4B 按句法角色/替换后通顺性判定），**但需要词表（lexicon），当前无词表源默认跳过**。

**词表红线**：词表须来自**会前 metadata**（参会名单/议程/往期纪要/项目名），**不能从答案抠**（旧 305 词表就是注水，不算数）。

**方案**：建**领域知识库**（人名/职务/机构/术语/项目/往期纪要），两种用法：
1. **RAG 召回纠错**：对 ASR 疑似专名（拼音候选）在 KB 里检索最相近的正确专名（embedding 检索，Qwen3-Embedding-0.6B 已选型）→ 有权威词表比纯拼音规则准；
2. **热词注入**：从 KB 取本场相关专名塞 ASR system 槽（hotword，**PC 已验证 B-WER 0.186→0.083、echo=0**，见 `docs/OPEN-ITEMS.md` parked 项，板端 C++ ~30 行待落）。

KB 构建：人工维护 + 从历史纪要/会议资料自动抽取（`build_lexicon` 已有「材料抽取优先」雏形）。

**依赖**：会前资料输入入口（**见方向 4**，两者耦合——没有资料输入，KB/hotword 就没合法词表源）；KB 存储轻量（专名表即可，RAG 走 embedding）。

**预期/验证**：专名召回↑（hotword 已证 B-WER 减半）；纠错精确率↑。验证走 `eval/transcription/` 的 B-WER/U-WER（不伤普通词）。

**诚实边界**：防**过纠**（把本来对的词改错）——沿用现有「句法角色 + 替换后通顺性」护栏；词表来源合法性是硬红线。

## 方向 3 · 专用理解性模型做分章

**动机（已测）**：分章是 4B 弱项（篇章级理解），演进已撞天花板——4B 自吐边界不可复现（4↔26 章漂移）；确定性 A 层可复现但边界切在长 Q&A 中间（Pk 0.497）；话语标记补到 Pk 0.190 但 **cue 泛化未做**；embedding 擅细粒度漂移、不擅粗粒度议题归组；主发言人边界 57% 是启发式天花板（`docs/技术演进.md` 分章演进表）。

**现状**：`stages/topic_segmentation.py`（v2）= 确定性信号（VAD gap / 说话人切换 / 词汇内聚谷深度）+ 尺寸切分；语义合并靠 4B 判 `continues_previous`。

**方案**：引入**专用话题分割 / 篇章理解模型**替代「启发式 + 4B 判定」——输入转写 Timeline，输出话题边界 + 章节标题。可选：
- 端侧小模型**专精分章**单任务（单任务往往比通用 4B 强）；
- 把话语标记检测器（`discourse_segmenter`）从正则升级为**学习式**（提 cue 跨会泛化）；
- 或云端离线预处理（若允许非纯端侧）。

**依赖**：分章标注数据（golden_v2 已有 `fine_chapters`，需更多标注）；端侧多一个模型的 NPU/内存预算（与 ASR/LLM **串行调度**）。

**预期**：边界召回↑、跨会泛化（不靠本会 cue）、更接近议程级边界。

**诚实边界**：分章质量看会而定、方差大；粒度无标准答案（飞书细 / 阿里粗）；端侧再加模型有资源成本，要权衡。

## 方向 4 · 前端开启「会议资料写入」（专名记录 + 加入口）

**动机（已测 + PRD）**：方向 2 的 KB/hotword 词表、方向 1/2 的域适配，**都需要会前资料输入**（参会名单/议程/往期纪要/专名表）——这正是 PRD 里的**合法词表来源**（会前 metadata），且 PRD P1 已列「会前议程 + 上次待办」。当前前端**没有**会议资料/参会人/术语的录入入口（新建会议只选音频）。

**现状**：前端有 会议库 / 新建(本地 WAV) / 处理 / 核对 / 正式纪要 / 回放 / 设置 页；Gateway `POST /api/meetings` 只收 `source_type`/`title`；域适配维度由 `stages/summary_profiles.py::DomainProfile` 承接（当前只有 generic）。

**方案（加前端入口）**：
1. **前端新增「会议资料」表单**（新建会议流程 或 会议详情里）：①参会人名单（→说话人/专名）②议程/主题③**专名/术语表**（人名/机构/项目/缩写）④往期纪要关联；
2. **Gateway** `/api/meetings` 扩展接收这些字段 → 存 `meeting_library`（SQLite，已持久化元数据）；
3. **下发板端** harness，作为：ASR **hotword 词表**（方向 2）+ 专名纠错 **KB/lexicon**（`postprocess` 注入点已存在）+ 摘要 **DomainProfile**（`summary_profiles` 已是此模式，插 profile 不改核心提示词）。

**依赖**：前端表单页 + Gateway 契约字段 + harness 注入（profile/hotword/lexicon 注入点均已存在，主要补前端与契约）。

**预期**：打通「会前资料 → 专名/域适配」闭环，让方向 2/hotword **真正可用**（有词表源）；符合 PRD 合法词表来源。

**诚实边界**：录音能力（pc_record/board_record）当前 = false（PRD P1 延期），本方向只做**资料/文本写入**；词表红线不变（会前来源，非答案）。

## 小结

| 方向 | 扣住的已测结论 | 主要依赖/成本 | 收益把握 |
|---|---|---|---|
| 1 微调 | 4B 弱归纳/低频；之前负结果=8G 所限非方法错 | **≥12-24G GPU** + 更多蒸馏数据 | 存疑（架构已绕开归纳）→ 先验 ROI |
| 2 KB/RAG 专名 | 残余漏项=专名；纠错缺词表源；hotword 已验 B-WER 减半 | 会前词表源（依赖方向 4） | **较高**（热词已证增益） |
| 3 分章模型 | 分章是天花板（Pk/57% 撞顶、cue 未泛化） | 标注数据 + 端侧模型预算 | 中 |
| 4 前端资料写入 | KB/hotword 需会前 metadata；PRD 合法来源 | 前端表单 + 契约 + harness 注入 | **闭环前置**（解锁方向 2） |
