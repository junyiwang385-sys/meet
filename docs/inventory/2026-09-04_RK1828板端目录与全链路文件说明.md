## 一、当前结论

当前板端采用“**新代码快照 + 共享运行资源**”的部署方式：

```text
新 Python 代码
  /userdata/meeting_agent1/mainline_cc9d83e/src/meeting_agent

共享板端脚本
  /userdata/meeting_agent/scripts

3D-Speaker 环境
  /userdata/3D-Speaker
  /userdata/miniforge3/envs/3dspeaker/bin/python

ASR runtime 和模型
  /userdata/meeting_agent/runtime/asr/...
  /userdata/meeting_agent/models/asr/...

Qwen3-4B 16K 模型和 RKLLM server
  /userdata/meeting_agent/models/llm/v104/qwen3-4b-v104-ctx16k
  /usr/bin/rkllm3-server
```

本次新快照来自：

```text
origin/feature/transcript-postprocess
commit: cc9d83e
```

注意：`mainline_cc9d83e` 当前部署的是 `src/meeting_agent` Python 包，不是把所有模型、3D-Speaker、音频和历史输出复制进快照目录。全链路实际依赖多个板端公共路径。

2026-09-03 的 5 组测试是**直接运行 Harness**，不是经由 Gateway/Board Agent：

```text
5/5 timing.status=succeeded
5/5 enrichment stage=succeeded
5/5 compat_export stage=succeeded
5/5 server.loaded_once=true
5/5 生成 enrichment.json
```

因此，直接 Harness 的结果已经证明新快照能够跑通；但在再次做“前端 → Gateway → Board Agent → Harness”测试前，仍应单独确认 `18082` 进程实际加载的 `PYTHONPATH`。

## 五、核心代码文件及作用

以下路径均以当前快照为基准：

```text
/userdata/meeting_agent1/mainline_cc9d83e/src/meeting_agent/
```

### 5.1 Board Agent 和 Worker

| 文件 | 内容与作用 |
| --- | --- |
| `adapters/board/board_agent_api_v0.py` | 板端 HTTP Agent；接收任务、接收音频、维护任务状态、启动后台 Harness Worker、返回安全结果投影。 |
| `adapters/board/board_harness_worker_v0.py` | 将 Board Agent 任务转换成 Harness 子进程；设置 `PYTHONPATH`、构造命令、轮询 `stage_status.json`、收集结果和诊断。 |
| `cli/board_agent.py` | Board Agent 的 Python CLI 包装入口。 |

### 5.2 Harness 入口和主编排

| 文件 | 内容与作用 |
| --- | --- |
| `harness/main.py` | 命令行解析入口；定义音频、脚本、ASR、LLM、RKLLM server 的默认路径；`--enrichment` 默认开启。 |
| `harness/pipeline.py` | 全链路主编排；按顺序运行分段、Batch ASR、转写准备、LLM 摘要、enrichment 和兼容导出。 |
| `harness/lifecycle.py` | 阶段状态、终态收尾、artifact 收集、metrics 写入和失败状态处理。 |
| `harness/errors.py` | Harness 阶段异常类型和错误边界。 |
| `harness/artifacts.py` | 兼容导出模块，转发到统一存储 artifact helper。 |

### 5.3 音频、转写和后处理

| 文件 | 内容与作用 |
| --- | --- |
| `stages/transcript.py` | 将 ASR 片段准备为 canonical transcript，生成 timeline，并维护时间戳和文本结构。 |
| `stages/postprocess.py` | 转写后处理；包含重叠文本确定性去重，以及可选的拼音候选/专名纠错。当前导入需要 `pypinyin`。 |
| `stages/topic_segmentation.py` | 基于转写内容和结构规则进行话题/章节分段。 |
| `stages/validation.py` | 摘要、章节、speaker、待办等结构化结果的校验。 |

### 5.4 纪要和 enrichment

| 文件 | 内容与作用 |
| --- | --- |
| `stages/product_summary.py` | 会议纪要主阶段；执行块摘要、完整概览、章节、发言人摘要、行动项候选和校验。发言人摘要位于 `summary["speakers"]`。 |
| `stages/summary_profiles.py` | 领域画像和摘要抽取规则配置；当前包含通用 profile。 |
| `stages/enrichment.py` | 在摘要后复用同一个 RKLLM session，生成关键词、问答回顾、金句、关键决策和层级大纲。失败时作为增强阶段处理，不应阻断主链路。 |
| `stages/display.py` | 将内部摘要转换为前端展示模型，包括章节、speaker summary、待办和转写展示。 |
| `stages/compat_export.py` | 生成兼容格式的 `transcription.json`、`auto_chapters.json`、`summarization.json`、`meeting_assistance.json` 和 `task_result.json`。 |

### 5.5 LLM 和观测

| 文件 | 内容与作用 |
| --- | --- |
| `llm/llm.py` | RKLLM server 生命周期、请求发送、响应解析、请求统计、server ready 信息和复用 session。 |
| `llm/chunking.py` | LLM 输入预算、分块和超长内容处理。 |
| `llm/ollama_session.py` | PC/Ollama 侧兼容 session；板端主路径使用 RKLLM session。 |
| `observability/runlog.py` | 追加写 `run_events.jsonl`，记录阶段开始/结束、进程和 artifact 事件。 |
| `observability/metrics.py` | 生成紧凑的 `run_metrics.json`。 |
| `observability/run_report.py` | 根据运行目录汇总 `run_report.json`，统计时延、enrichment、server 单次加载和内存。 |
| `observability/error_report.py` | 失败时生成受限错误报告，不应嵌入完整 prompt 或原始模型响应。 |

### 5.6 公共基础模块

| 文件 | 内容与作用 |
| --- | --- |
| `storage/artifacts.py` | 定义 Harness 输出目录结构、原子写文件、SHA-256 和相对 artifact 引用。 |
| `contracts/identity.py` | `run_id`、`meeting_id`、`task_id`、`trace_id` 等身份字段。 |
| `contracts/errors.py` | 错误标准化、错误码和安全文本投影。 |
| `contracts/results.py` | 结果和 sidecar schema 版本常量。 |
| `__init__.py` | 包版本和本地优先项目标识。 |

## 六、当前 Harness 全链路顺序

```text
输入 WAV
  │
  ├─ 1. segmentation
  │     3D-Speaker / VAD / speaker 分段
  │     输出 01_segments
  │
  ├─ 2. batch_asr
  │     Qwen3-ASR 批量转写
  │     输出 02_batch_asr
  │
  ├─ 3. transcript_prepare
  │     整理 ASR 片段、重叠去重、生成 canonical transcript/timeline
  │     输出 timeline.txt、03_llm_summary/canonical_segments.json
  │
  ├─ 4. llm_summary
  │     启动一次 rkllm3-server
  │     块摘要 → 完整概览/章节 → speaker 摘要/待办
  │     输出会议纪要和 LLM 诊断
  │
  ├─ 5. enrichment
  │     复用 llm_summary 已启动的同一个 RKLLM server
  │     输出关键词、问答、金句、决策、层级大纲
  │
  └─ 6. compat_export
        生成兼容格式导出文件
```

### 6.1 各阶段最重要的外部文件

| 阶段 | 必须存在的文件/目录 | 作用 |
| --- | --- | --- |
| segmentation | `/userdata/meeting_agent/scripts/board_3dspeaker_segment_prepare_absorb_unknown.py` | 调用 3D-Speaker，执行 VAD/分段/unknown 后处理。 |
| segmentation | `/userdata/3D-Speaker/speakerlab/bin/infer_diarization.py` | 3D-Speaker 推理入口。 |

| batch_asr | `/userdata/meeting_agent/models/asr/qwen3-asr-0.6b-rknn` | ASR 模型文件目录。 |

| `meeting_summary.json` | 内部证据关联纪要；包含 title、overview、chapters、speakers、action_items 等。 |
