# meet 评测线完整规划

> 2026-09-04 起草。三层评测栈：L1 确定性指标（主判据）+ L2 校准过的单维 LLM 裁判（参考）+ L3 两两盲评回归（版本决策）。
> 方法论来源：MESA（单维裁判+校准）、CREAM（对比代替打分）、P-MESA（维度清单）、ACL'26 长文档事实一致性压测（NLI/QA 系指标长输入失灵 → 走证据锚点确定性路线）。

## 0. 设计原则（先定死，避免走偏）

1. **L1 确定性指标是主判据，裁判层只做参考和趋势**——上线/回退决策看 L1 + L3 胜率，不看裁判绝对分。
2. **裁判先校准后使用**——裁判和人工金标的一致率不达标（<80%）就不采信该维度。
3. **全流程本地**——裁判跑 PC Ollama，不出网，和项目隐私叙事一致。
4. **每层产物落结构化 JSON**，汇进现有 `run_eval.py` 聚合，延续「零手填」路线。
5. 裁判也是 LLM，同样吃 CLAUDE.md 的能力边界约束：**一次一任务、单维评估、强 schema、不用 few-shot**。

## 3. 分阶段实施

### 阶段 0 · 裁判环境（半天）
- 4060 8GB 显存下选裁判：`qwen3:8b` 全进显存（首选）；`qwen3:14b` 部分 offload 慢但批量评测可接受。两个都拉，校准阶段用数据说话选一个。
- `judge_client.py`：temperature=0、强制 JSON schema 输出、容错解析（复用 enrichment 的 `_loads_tolerant` 经验）。

### 阶段 1 · L1 补强（1 天）
- **锚点支持率**：抽摘要要点 → 取其 refs 指向的原文段 → 词面重叠初筛（数字/专名必须命中）→ 可疑项输出人工复核清单。产出 `anchor_support_rate` + 可疑清单。
- 把 L1 全指标（recall / Pk / 金句保真 / 校验失败率 / 锚点支持率）统一成一个 `L1Report` JSON，进 `run_eval.py`。

### 阶段 2 · 裁判校准（1 天，关键闸门）
- 用 3 组金标会议：裁判评「该关键点是否被摘要覆盖」，和人工标注的 真漏/半真漏/覆盖 三分类对比，算一致率。
- 8b vs 14b 各跑一遍 → 选一致率高且够快的。
- **一致率 <80% 的维度直接砍掉不上 L2**——这个闸门本身写进报告，是评测线可信度的证据。

### 阶段 3 · L2 单维裁判（1 天）
- 只上两维：
  - **忠实度**：摘要句是否被原文支持，按章节分块喂（避开长文一起编码的失灵坑）。
  - **完整性**：金标外的启发式——决策/待办/负责人是否成对出现。
- 实现选型：先手写（judge_client + 每指标一个 prompt+解析）；DeepEval 包装放最后一步，只为 CI 门禁和简历关键词，不为核心逻辑。
- 输出趋势值，不设硬阈值。

### 阶段 4 · L3 两两盲评回归（1 天）
- `pairwise.py`：输入两个版本的 `meeting_summary.json` → 同一会议按维度（忠实/完整/可读）盲评；A/B 随机换位跑两次防位置偏置，不一致记平局 → 胜率表。
- **第一个真实用例已排好**：004 板端新代码产出 vs 003 的 g1–g5，直接回答「QA 错配/占位待办/合并率三处修复到底有没有变好」。

### 阶段 5 · 串成一条线（半天）
- `run_eval.py` 聚合三层 → `RESULTS.md` 增加 L2 趋势表、L3 胜率表。
- pytest 入口：`test_eval_gate.py` 只对 L1 设硬阈值（recall≥0.8、锚点支持率≥0.9、校验失败率=0），L2/L3 打印不拦截。
- 可选收尾：L1 指标包成 DeepEval 自定义 Metric，`deepeval test run` 可跑——简历口径「自建指标接入 DeepEval CI 门禁」成立。

## 4. 执行顺序与依赖

```
阶段0 ──> 阶段2(校准) ──> 阶段3(L2) ─┐
                                     ├──> 阶段5(串线)
阶段1(L1补强，无依赖可先做) ─────────┤
阶段4(L3，只依赖阶段0) ──────────────┘
```

总量约 **4–5 个工作日**。最快见效路线：**阶段 0 → 阶段 4**（两天内 L3 对比就绪，赶在 004 板端结果回来之前），校准和 L2 随后补。

## 5. 风险与边界（诚实条款）

- 8GB 显存跑 14b 裁判可能慢到不实用 → 校准阶段实测，慢就锁 8b。
- 裁判校准集只有 3 会 ~30 个关键点，一致率有噪声 → 结论写「初步校准」，后续每标一会金标顺手扩充。
- L2/L3 结论均为 PC 裁判所出，**不写进板端性能叙事**；面试口径：「确定性主判据 + 校准过的本地裁判参考层」。
