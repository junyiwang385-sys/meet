## 结论（诚实）

1. **内容理解好**：决策/待办**内容覆盖 0.81 / 0.89**、core 召回 0.80——4B 把关键内容**理解到了、也写进了纪要正文**。
2. **待办结构化——修前不稳定塌缩,已加地板修复(2026-09-14)**：
   - 修前:各场 1/8、9/1、1/6、1/3——多数**塌成 1 条**(静默丢待办),g2 又过产。根因=qwen3:4b 的
     action-review 时而不按 `{"action_items":[...]}` 包裹、把多候选塌成一个对象。
   - 修复(`product_summary._actions_from_candidates` + 塌缩检测退回块级候选,见代码):
     塌缩消除,待办不再丢——g1/g3/g5 从 1 回到 12/12/9。
   - **诚实代价 = recall/precision 权衡**:修后稳定**高于金标**(12 vs 8、9 vs 3),因块候选含跨块重复 +
     金标未收录项,**精度低于 LLM 成功归并那次**。即问题从"不稳定塌缩(丢)"变成"稳定候选地板(过产)"。
   - 残留(未做):候选去重仅按 task 文本,跨块同义待办仍可能重复;**提精度**是下一步(更强去重或让 4B 只做合并不做丢弃)。
3. **决策结构化数量≈金标**(13–17 vs 9–22),但**选题不完全一致**(覆盖 0.68–1.0)。
4. **金句逐字保真 = 12/12 = 100%**——干净正面:snap-to-transcript 有效,金句是真原句、非改写。
5. **发言人纪要覆盖 ~0.85**(5–6/7)——漏的多是低内容/unknown 说话人。

## 诚实边界

- **覆盖**是 token 半命中的 proxy(非精确匹配)；**产出**是计数比(非召回,>1=过产)——两者都不是干净召回/精确率。
- 参考为**银标**(LLM 生成+核验)、**文本比对**(seg-id 不同源无法对齐)、**n=4 同分布**(AliMeeting 剧本会)。
- 用途:多场**方向性**质量判断,把 enrichment/发言人/待办 从"无评测"升为"有据",**非发布级质量门**。
