# 评测体系框架化 · 执行计划

> 目标:把散乱的 62 脚本 / 3 套裁判 / 多召回口径,收敛成**一套契约、一个入口、无 key 可复现、可进 CI**。
> 原则:**收敛你已有的,不为用 DeepEval 而 DeepEval**;确定性做门禁,裁判做趋势(校准后)。
> 起草 2026-09-14。分 6 阶段,A/B/C 三档对应必做/值得/看简历。

---

## 0. 框架化后的目标形态

```
eval/
├── run_all.py            ★唯一入口:一键跑正式指标 → reports/RESULTS_main.{md,json}
├── config/               会议清单 / 阈值 / 裁判选择(数据驱动,零手填)
├── golden_v2/            银标 + 确定性摘要指标(score_candidate 召回 / score_dimensions 维度)+ 银标流水线
├── conformance/          ★决策符合度(全 LLM):judge_prompt + run_conformance → over/missed/critical/忠实度
├── judge/
│   ├── ollama_judge.py   ★本地裁判(无 key,默认,L2 趋势/CI)
│   ├── opus_judge.py     ★权威裁判(opus 子agent,决策符合度/校准)
│   ├── qwen_judge.py     云千问(可选,设 key 才用)
│   └── calibrate.py      校准闸(对存档/人工一致率 ≥0.8 才采信)
├── metrics/              DeepEval L1 确定性 + GEval(裁判改本地)
├── transcription/        转写线(独立入口,不并入 run_all)
├── topic_segmentation/   分章线(独立入口)
├── experiments/          已归档实验(结论在 README)
└── reports/RESULTS_main  自动生成的主报告
```

**分层契约(每个指标一个定位,消除歧义)**:

| 定位 | 指标 | 算法 | 金标 |
|---|---|---|---|
| **硬门禁**(确定性,过不了 CI 红) | 锚点支持率=1.0 · 金句逐字保真 · core_fact 召回≥地板 | 确定性 | 银标 |
| **地板召回**(确定性,饱和) | core_fact 召回 + 低频召回 | 半命中 | 银标 core_facts |
| **质量参考**(确定性 proxy) | 决策/待办覆盖 · 产出比 · 关键词纯净 · owner 归属 | jieba/计数 | 银标 |
| **趋势**(裁判,校准后) | **忠实度 · over_decision · missed_decision · critical**(全 LLM)· 完整度 | opus/本地裁判 | 银标 status 标签作权威锚 |
| **仅校准用** | 人工 keypoint 召回 | 半命中 | 人工 5 场 |

## 顺序 / 总成本 / 不做

```
阶段0(基座) → 阶段1(决策全LLM) → 阶段2(入口聚合) → 阶段3(CI) → 阶段4(文档)
                                                    └ 阶段5(L3,可选,只依赖阶段0)
```

- **A 档(必做)= 阶段 0+1+2+4**:约 **3-3.5 天**,产出"一套契约、一个入口、无 key 可复现、文档对齐"。
- **B 档 = 阶段 3**:+1 天,CI 门禁 + 简历口径成立。
- **C 档 = 阶段 5**:+2 天,按简历需要。

**明确不做**:不铺 DeepEval 当核心、不改转写/分章线逻辑、不改产品代码(除评测口径)、不追求人工 gold(继续用银标 + 诚实边界)。

**贯穿风险**:裁判波动(阶段1)——靠校准闸 + temp0 + 固定提示词 + K-run 压;裁判层一律**趋势不设硬门禁**,硬门禁只给确定性指标。
