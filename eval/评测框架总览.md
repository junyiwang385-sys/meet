# meet 评测框架总览（金标 · 评测线 · 指标 · 方法论）

> 交接/复盘用。把散在 `eval/` 各处的评测体系整理成一张全景图。截至 2026-09-14，以代码为准。
> 一句话：**三层评测栈（L1 确定性主判据 / L2 校准裁判参考 / L3 两两盲评回归）+ 三模型分离 + 全流程本地 + 零手填**。

---

## 一、设计哲学（先定死的原则）

来源：`eval/评测线规划.md`（方法论参考 MESA 单维裁判+校准、CREAM 对比代替打分、P-MESA 维度清单、ACL'26 长文档事实一致性——NLI/QA 系指标长输入失灵 → 走**证据锚点确定性**路线）。

1. **L1 确定性指标是主判据，裁判层只做参考/趋势**——上线/回退看 L1 + L3 胜率，不看裁判绝对分。
2. **裁判先校准后使用**——裁判 vs 人工金标一致率 <80% 就不采信该维度（`judge/calibrate.py`，实测 g1/g2=0.818 达标）。
3. **三模型分离**（避免自评偏置）：**候选=本项目 4B / 金标=fable5 生成 + opus-5 核验 / 裁判=opus-5 或千问**，三方独立。
4. **全流程本地**：裁判可跑 PC Ollama / 云端千问 / Claude 子agent，均只评测、不影响端侧离线部署。
5. **每层产物落结构化 JSON**，零手填。
6. **裁判也是 LLM**，同吃 CLAUDE.md 能力边界：一次一任务、单维评估、强 schema、不用 few-shot。

三层栈：

```
L1 确定性指标（主判据，硬阈值门禁）
   └─ 对金标/结构，可复现、可回归
L2 单维 LLM 裁判（校准后参考，趋势值）
   └─ 忠实度/完整度等，需先过 ≥0.8 校准闸
L3 两两盲评回归（版本决策，CREAM-lite）
   └─ A/B 换位盲评 → 胜率表，回答"这版有没有变好"
```

## 二、金标体系（三套，粒度/来源不同，勿混比）

| 金标 | 位置 | 规模 | 来源 | 结构 |
|---|---|---|---|---|
| **golden_v2 银标**（主） | `golden_v2/out/*.golden.json` | **30 场**（AliMeeting train_L） | **fable5 生成 + opus-5 独立核验**（源官方 Praat TextGrid） | `core_facts`(带 anchors/importance) · `decisions`(**带 status=decision/proposal**) · `action_items`(owner/deadline) · `fine_chapters` · `speakers` |
| 人工 keypoints | `golden/*.keypoints.json` | 5 场 | 人工标注 | `key_points`(desc + anchors)；兼做裁判校准集 |
| 对标 judge 数据 | `reports/对标数据/judge_*.json` | 5 份（飞书/阿里/ours） | opus-5 裁判产出 | claims/faithfulness/over_decisions/missed_decisions/critical |

**银标生成流水线**（`golden_v2/`，四阶段，均出提示词手动喂 Claude）：
`build_timeline.py`（TextGrid→带 seg-id 参考时间线 + speech_end 截断 QA 门）→ `gen_prompt.py`（**fable5** 生成金标）→ `validate_golden.py`（结构硬校验）→ `verify_golden.py`（**opus-5** 独立核验，`verify/*.verify.json`）→ `render_review.py`（HTML 审阅页）。

> ⚠️ **是"银标"非人工 gold**；分章 fine_chapters 是"更细参照系"非唯一正确切法；g2 官方 TextGrid 截断在 22:07（30 场仅此触发截断门）。

## 三、五条评测线（按链路/维度）

### 线 1 · 转写线 `transcription/`（标准口径 jiwer/pyannote）

AliMeeting 30 场，四个点 + 参数扫描。对官方 TextGrid/rttm 参考。

| 点 | 脚本 | 指标 |
|---|---|---|
| 点1 VAD | `run_point1_vad` · `run_vad_sweep` · `run_p1_full30` · `run_p1_remeasure` | FA(collar0.25) · 真信息丢失(>2s 话语整句丢) |
| 点2 说话人分离 | `run_point2_diar` · `score_board_diar` | DER · 纯度/覆盖 |
| 点3 ASR | `run_point3_asr` · `score_asr` | CER · **B-WER/U-WER**（热词偏置 A/B） |
| 点4 端到端 | `run_point4_e2e` · `run_p4_board_ba` | 端到端 CER（前端丢失主导） |

关键结论：VAD `speech_noise_thres` 0.6→**0.2**（整句丢 28%→9%，全 30 场泛化）；热词 B-WER 0.186→0.083；端到端 CER 被前端(VAD/分离)丢失主导 > ASR 听错。规范化口径 `transcription/normalize.py`。

### 线 2 · 分章线 `topic_segmentation/`

| 脚本 | 指标 |
|---|---|
| `pk_windowdiff.py` | **Pk / WindowDiff**（越低越好） |
| `cohesion_boundary_recall.py` | 边界召回（字符 bigram vs 句向量内聚） |
| `discourse_segmenter.py` | 话语标记(discourse cue)边界补测 |
| `run_seg_v2_blocks.py` · `run_seg_v2_multi.py` | A 层 segment_blocks 单场/多场(3-5) |

结论：A 层确定性分块，多场边界召回 ~0.30/Pk0.432（对银标细章偏粗）；话语标记单场 Pk→0.190。

### 线 3 · 摘要质量线 `golden_v2/`（**核心**）

**3a 确定性召回/维度**（对银标，L1）：
- `score_candidate.py`：**core_fact 锚词半命中召回** + **低频召回**（anchor 含数字子类，4B 软肋）。
- `score_dimensions.py`（`--clean` 支持 n=30 干净输入线）：**内容覆盖**（决策/待办 jieba 半命中）· **结构化产出**（计数比，>1=过产）· **金句逐字保真**（quote 是否转写子串）· 发言人覆盖 · enrichment 计数。

**3b 符合度裁判**（对标 opus-5，L2，**P0/P1 核心**，见 `reports/对标飞书阿里_符合度.md`）：
- **忠实度** = (supported + 0.5·partial) / claims 数（逐条 claim 对逐字时间线判 supported/partial/unsupported/contradiction）。
- **决策符合度**（靠金标 `status` 权威标注，**逐条**比对，非主观再判）：
  - **over_decision** = 候选把金标 `status=proposal` 的项，放进自己的**决策/待办字段**（升格）。
  - **missed_decision** = 金标 `status=decision` 的真决定，候选没捕获。
  - **critical** = 编造数字/owner/待办（原文无据）。
  - verdict = ok/weak/fail。

### 线 4 · DeepEval 套件 `deepeval_suite.py` + `metrics/` + `judge/`

业界 DeepEval 框架封装，8 指标两层（`eval/README.md`）：

| 层 | 指标 | 实现 |
|---|---|---|
| **L1 确定性** | 关键点召回 / 低频精确召回 | `metrics/keypoint_recall_metric.py` |
| L1 | **锚点支持率**（refs 落真实原文段=证据可回溯，卖点） | `metrics/deterministic_metrics.py` `AnchorSupportMetric` |
| L1 | 关键词纯净度（议题词占比，量化 P1 去噪） | `metrics/deterministic_metrics.py` `KeywordPurityMetric` |
| L1 | 决策 owner 归属率（对标飞书说话人归属） | `metrics/deterministic_metrics.py` `DecisionOwnerMetric` |
| **L2 裁判** | 忠实度 / 完整度 / 简洁相关度（G-Eval） | `metrics/geval_metrics.py`，裁判=千问 qwen3.8-max |

裁判校准 `judge/calibrate.py`（一致率 ≥0.8 才采信）；千问接入 `judge/qwen_judge.py`（DashScope，需 `DASHSCOPE_API_KEY`）。

> 裁判可替换：套件默认千问；也可用 **Claude 子agent(opus)** 作裁判（与 fable5/opus5 金标流程一致，无需外部 key）——`run_deepeval_clean.py`（L1，n=30 干净线）、`judge_conformance.py`（opus 符合度裁判提示词构造器）。

### 线 5 · 微调线 `finetune/`（负结果）

`build_train_pairs`（train_S→A0 块对）→ `train_qlora`（Qwen3-4B 4bit+LoRA）→ `eval_finetune`（base vs +LoRA 对 train_L held-out core_fact 召回）。结论：**召回 0.167→0.024，弃**（8G 显存约束）。

### 设计取舍实验组（`eval/*.py` + `golden_v2/pc_*.py`）

块大小 `chunk_size_experiment`、上下文 `context_experiment`、双边 carryover `bilateral_context_experiment`(A3b)、A0vsA1 `a0_vs_a1_production`、批量 `batch_summary_experiment`、去噪 `pc_denoise_experiment`（must_cover 证伪回退 −5pp）、热词 `pc_hotword_ab`、关键词 `pc_keyword_*`、打捞 `pc_salvage*`/`pc_exhaustive_recall`。

## 四、指标总表

| 指标 | 层 | 实现 | 对什么 | 性质 |
|---|---|---|---|---|
| core_fact 召回 / 低频召回 | L1 | `score_candidate.py` | 银标 core_facts | **地板门槛**（强候选饱和，见 §五） |
| 内容覆盖 / 结构化产出 / 金句逐字 | L1 | `score_dimensions.py` | 银标 decisions/actions/quotes | 确定性维度 |
| 关键点召回 / 低频 | L1 | `keypoint_recall_metric.py` | 人工 keypoints(5) | 判定依据 |
| 锚点支持率 | L1 | `deterministic_metrics.py` | 候选 refs↔原文段 | 证据可回溯（卖点） |
| 关键词纯净度 | L1 | 同上 | 候选 keywords | 量化 P1 去噪 |
| 决策 owner 归属率 | L1 | 同上 | 候选 decisions | 对标飞书归属 |
| **忠实度** | **L2/P0** | `geval_metrics`(千问) 或 `judge_conformance`(opus) | 候选 claims↔逐字时间线 | **竞争力分野** |
| **over_decision / missed_decision / critical** | **L2/P0** | opus 裁判（决策靠金标 status 逐条比对） | 候选↔银标 decision/proposal | **竞争力分野 + 卖点红线** |

| held-out core_fact 召回 | 微调 | `finetune/eval_finetune` | train_L | 负结果依据 |

## 五、P0/P1 权重（评测框架最关键的洞察）

来源：`reports/对标飞书阿里_符合度.md` 结论 3。

> **锚词召回饱和、无分辨力**（飞书/阿里两场全 1.0）→ **退为"地板/漏检"检测器**，不是竞争力标尺。
> **忠实度 + 决策符合度（over_decision/missed/critical）才是竞争力分野** → **这两项是 P0/P1 核心权重项**。

对标实测（g1 干净场，三方）：

| 维度 | 我们(4B) | 飞书 | 阿里 |
|---|---|---|---|
| 忠实度 | 0.89 | 0.953 | 0.833 |
| **over_decision（提议→决定）** | **0** ✅唯一 | 6 | 6 |
| missed_decision | 5 | 0 | 4 |
| critical 编造 | 3 | 1 | 3 |

**两种失败模式**：我们=保守（漏 5/9 真决定，但决策纪律最好 over=0）；竞品=激进（覆盖满分，但把提议写成决定各 6 条 + 也编）。**微调方向**：保住"决策不升格"纪律前提下，补覆盖（召回+漏决定）、压 critical。

> ⚠️ 该 over_decision=0 为 **n=2 结论**。2026-09-14 用确定性逐条比对复现 board g1 = over 0（✓），但 n=30 干净线上 over 均 ~1.4/场、7/30 为 0——**"零升格"应修正为"升格很少"**（低但非零）。missed/critical/忠实度仍需 opus 裁判逐场判（确定性做不了 missed 的语义匹配）。

## 六、诚实边界

1. **PC 等价替代非板端复现**（Ollama GGUF Q4 / transformers），方法论可信、绝对值板端差 ~5%。
2. **金标是银标**（fable5+opus5），非人工 gold；人工 keypoints 仅 5 场。
3. **少场**（n=2 对标 / n=4-30 维度 / 30 场转写），非大规模 benchmark。
4. **长会 1-2h（卖点）完全未验**。
5. 裁判层（L2/L3）结论**不写进板端性能叙事**；口径="确定性主判据 + 校准过的裁判参考层"。
