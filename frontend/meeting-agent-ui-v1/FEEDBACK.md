## 问题清单

### 1. 执行过程中进度条长时间不动

- **现象**：会议处理期间进度条容易停留在同一个位置，用户无法判断任务是否仍在执行。
- **期望**：只要任务处于上传、转写、摘要或导出等非终态，界面应有持续可见的活动反馈。
- **建议**：
  - 有后端真实进度时显示真实进度。
  - 没有可靠百分比时使用阶段进度或不确定进度动画，不要伪造精确百分比。
  - 阶段发生变化时同步更新进度文案和视觉状态。
  - 任务进入成功、失败、取消后停止动画。
- **验收**：任务未进入终态时，进度区域不会长期呈现静止状态；终态后动画停止并保留最终结果。

### 2. 缺少执行时间和清晰的任务状态

- **现象**：处理页面未持续显示用户关心的已执行时间、当前状态和当前阶段，等待期间缺少明确反馈。
- **期望**：显示并实时更新：
  - 任务状态：等待、上传中、处理中、已完成、失败、已取消。
  - 当前阶段：转写、说话人处理、纪要生成、结果导出等。
  - 已执行时间。
  - 完成或失败后的总耗时。
- **验收**：页面刷新或轮询后状态与 Gateway 返回一致；任务结束后总耗时仍可查看。

### 3. 转写完成后无法直接查看转写结果

- **现象**：转写阶段完成后，页面没有提供可进入、展开或查看转写文本的明确入口。
- **期望**：转写完成后即可在前端查看转写结果，至少包含：
  - 转写文本。
  - 说话人标识（如果后端已提供）。
  - 时间戳或分段信息（如果后端已提供）。
  - 加载中、暂无结果、加载失败等状态。
- **验收**：当后端返回转写可用状态时，处理页面或结果页面出现可操作的“查看转写”入口；点击后能读取对应会议的转写内容，不需要访问本地文件目录。

### 4. 纪要草稿和最终纪要无法保存

- **现象**：纪要草稿无法保存，最终纪要也无法保存或生成可留存版本。
- **影响**：用户无法修改、保留或确认会议纪要，结果链路无法闭环。
- **期望**：
  - 纪要草稿支持保存、再次打开和继续编辑。
  - 保存过程中显示保存中、保存成功或保存失败状态。
  - 保存失败时显示明确原因和可重试入口。
  - 最终纪要支持保存为产品要求的正式版本格式，例如 HTML、TXT、JSON。
  - 保存后能从会议详情或导出入口再次读取。
- **建议排查**：
  - 前端保存请求的 URL、HTTP 方法和请求体。
  - Gateway 对草稿和 finalize/export 接口的返回状态。
  - 会议库目录是否存在、是否可写。
  - 纪要状态和保存能力字段是否与前端按钮状态一致。
  - 保存失败时是否被前端静默吞掉。
- **验收**：草稿保存后刷新页面仍能恢复；最终纪要保存后可从会议详情重新打开并导出；失败场景有明确错误提示。

## 优先级建议

| 优先级 | 问题 | 原因 |
| --- | --- | --- |
| P0 | 纪要草稿和最终纪要无法保存 | 直接阻断人工核对和正式版本产出 |
| P0 | 转写完成后无法查看转写结果 | 阻断用户核对转写和说话人结果 |
| P1 | 缺少执行时间和清晰状态 | 用户无法判断任务是否正常进行 |
| P1 | 进度条长时间不动 | 容易被误判为卡死，需要持续活动反馈 |

## 完成标准

```text
前端启动任务
  -> 进度区域持续反馈
  -> 显示当前阶段、状态和已执行时间
  -> 转写完成后可查看转写
  -> 纪要草稿可保存并恢复
  -> 最终纪要可保存、重新打开和导出
```
